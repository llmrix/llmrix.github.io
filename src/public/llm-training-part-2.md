# 模型训练技术体系全解析（中篇）

模型训出来之后的四个问题：跑不下怎么办（分布式训练）、怎么针对任务改造（微调）、怎么让它听话（对齐）、怎么把它变小（量化压缩）。

---

# 五、分布式训练

单张 GPU 训练大模型已成历史。一张 A100 80GB 连 70B 模型的参数都装不下（70B × 2 bytes/param ≈ 140GB）。分布式训练是大模型存在的基础设施前提。

---

## 5.1 并行策略体系

### 数据并行（Data Parallelism, DP）

每个 GPU 持有完整的模型副本，处理不同的数据子集。反向传播后通过 All-Reduce 操作同步梯度，更新各自的模型副本。

- **优点：** 实现简单，通信量相对可控
- **限制：** 模型必须能放进单张 GPU

### 张量并行（Tensor Parallelism, TP）

将单个矩阵乘法操作按列或按行切分到多个 GPU 上并行计算，让单层的参数分布在多张 GPU 上，解决"模型太大放不下"的问题。

- **优点：** 解决单层显存瓶颈
- **限制：** 每层前后都需要 All-Reduce 通信，要求 GPU 间有高带宽互联（NVLink）

### 流水线并行（Pipeline Parallelism, PP）

将模型的层（Layer）按顺序分配到不同 GPU：

```
GPU 0：第 1-8 层
GPU 1：第 9-16 层
GPU 2：第 17-24 层
```

Batch 被切成 micro-batch，流水线式通过各 GPU。

**流水线气泡（Pipeline Bubble）：** 流水线启动和收尾阶段，部分 GPU 处于等待状态，产生计算空洞。Interleaved Pipeline 等技术可降低气泡率。

- **优点：** 通信量小，可扩展到数百 GPU
- **限制：** 存在气泡，实现复杂

### 序列并行（Sequence Parallelism, SP）

处理超长序列（如 128K context）时，将长序列按位置切分到不同 GPU 上处理。注意力层需要跨 GPU 通信完成注意力计算（Ring Attention 是代表算法）。常与 TP 组合使用。

### 专家并行（Expert Parallelism, EP）

MoE 模型专属。不同专家网络分布在不同 GPU 上，每个 token 由路由器决定发给哪个专家处理。

## 5.2 显存优化技术

### 梯度检查点（Gradient Checkpointing）

正常训练时，前向传播的中间激活值全部保留在显存中，供反向传播计算梯度，显存开销大。

梯度检查点只保留部分层的激活值，其余丢弃。反向传播需要某层激活值时，从最近的检查点重新执行前向传播。

- **代价：** 前向传播多执行约 1.33 倍
- **收益：** 显存节省 60-70%

```python
from torch.utils.checkpoint import checkpoint_sequential
output = checkpoint_sequential(model.layers, segments=4, input=x)
```

### ZeRO（Zero Redundancy Optimizer）三级分片

以 7B 模型 FP32 为例，单卡需要：
- 参数：7B × 4 bytes = 28GB
- 梯度：28GB
- Adam 优化器状态（m 和 v）：56GB
- **合计：~112GB**，远超单张 A100

ZeRO 的思路：将这些状态分片存储到各 GPU，用时再聚合。数据并行本来就要同步梯度，分片存储不引入额外通信，只是改变了存储方式。

| ZeRO 级别 | 分片内容 | 8 卡时单卡节省 |
|---------|--------|-------------|
| **ZeRO-1** | 优化器状态 | 优化器状态从 56GB → 7GB/卡 |
| **ZeRO-2** | 优化器状态 + 梯度 | 梯度从 28GB → 3.5GB/卡 |
| **ZeRO-3** | 优化器状态 + 梯度 + 参数 | 参数从 28GB → 3.5GB/卡 |

### CPU / NVMe Offloading

GPU 显存不足时，将暂时不用的数据搬到 CPU 内存（更大但更慢），甚至 NVMe SSD。DeepSpeed ZeRO-Infinity 支持将优化器状态 offload 到 CPU。

PCIe 带宽远低于 NVLink，offloading 越多训练越慢。CPU offloading 可接受，NVMe offloading 仅用于显存极度紧张的推理场景。

## 5.3 通信优化

### All-Reduce 与 Ring All-Reduce

All-Reduce 的任务：将 N 张 GPU 上的梯度求和，然后广播给所有 GPU。

**朴素实现（中心化）：** 所有 GPU 把梯度发给一个中心节点，中心节点汇总后再发回。中心节点成为带宽瓶颈。

**Ring All-Reduce：** 所有 GPU 排成一个环，每次将部分数据传给相邻节点，同时接收另一个方向的数据。绕环两圈后，每张 GPU 都持有完整的梯度总和。通信量不随 GPU 数量线性增加，扩展性极好。这是现代 NCCL 的核心算法。

### 通信与计算重叠（Overlap）

不等梯度全部算完再开始通信——哪个层的梯度计算完毕，立即开始通信这个层的梯度，同时 GPU 继续计算其他层的梯度。理论上可将通信时间完全隐藏在计算时间内。

### 节点内 NVLink vs 节点间 InfiniBand

| 互联方式 | 典型带宽 | 适用场景 |
|---------|---------|--------|
| NVLink 4.0（A100） | 900 GB/s 双向 | 节点内 8 卡通信（TP、ZeRO） |
| NVLink 5.0（H100） | 1800 GB/s 双向 | 节点内极高带宽 |
| InfiniBand HDR | 200 Gb/s 单向 | 节点间（PP、DP） |
| InfiniBand NDR | 400 Gb/s 单向 | 大规模集群节点间 |

**核心原则：** 通信量大的并行维度（TP）放节点内（NVLink），通信量小或可重叠的（PP、DP）放节点间（IB）。

- **TP（节点内）：** 等于节点内 GPU 数（通常 8）
- **PP（节点间）：** 8-32，根据模型层数和节点数调整
- **DP（外层）：** 总 GPU 数 / (TP × PP)

配置经验法则：
- TP 度不超过单节点 GPU 数（NVLink 内通信）
- PP 度建议是模型层数的因数（如 96 层模型用 PP=8，每级 12 层）
- 确保 DP Batch Size 足够大以保证训练效率

# 六、微调技术（Fine-tuning）

预训练赋予模型知识，但预训练模型不会遵从指令，也不知道如何礼貌地回应用户。微调将预训练模型改造为可用的任务专家。

---

## 6.1 全参数微调 vs 参数高效微调

**全参数微调（Full Fine-tuning）：** 重新训练所有参数。效果最好，但成本极高，且容易覆盖预训练的通用知识（灾难性遗忘）。

**PEFT（参数高效微调）：** 只训练模型中极少数的参数（通常 <1%），其余参数冻结。

### 何时值得全参数微调

- 数据量极大且领域差异显著（如医疗垂直领域持续预训练）
- 需要改变模型的基础行为（如将英语模型改造为中文优先）
- 有充足计算资源（多台 A100/H100 集群）
- 不需要保留通用能力（专用领域模型）

### 灾难性遗忘

全参数微调时，模型过度优化目标任务，同时覆盖掉原来的知识（数学、代码、常识）。

缓解策略：

| 方法 | 原理 | 代价 |
|------|------|------|
| **混入通用数据** | 微调数据中加入 5-10% 通用数据 | 需要准备通用数据集 |
| **低学习率** | 用 1e-5 以下小学习率，小步微调 | 收敛更慢 |
| **PEFT 方法** | 冻结大部分参数，从根本上避免遗忘 | 表达能力略弱于全参数 |

---

## 6.2 PEFT 方法体系

### LoRA（Low-Rank Adaptation）

LoRA 基于一个观察：大模型参数矩阵在微调时的变化量（ΔW）往往是低秩的——可以用两个小矩阵的乘积来近似。

微调时不直接修改原始权重矩阵 `W`，而是在旁路新增一个低秩分解：

```
输出 = xW + x(A × B)
```

其中 `A` 是 `d × r` 矩阵，`B` 是 `r × d` 矩阵，`r` 是秩（rank），通常设为 4、8 或 16。

参数量对比（以 4096×4096 矩阵为例）：
- 原始参数：4096 × 4096 = **16,777,216**
- LoRA 参数（r=8）：4096×8 + 8×4096 = **65,536**（仅原来的 0.4%）

初始化：`A` 用随机高斯，`B` 初始化为零（训练开始时旁路输出为零，不干扰预训练权重）。

推理时可将 `BA` 合并回 `W`，不引入推理延迟：`W' = W + BA × α/r`

**LoRA 超参数：**

| 参数 | 含义 | 推荐值 |
|------|------|------|
| `r` | 秩，越大表达能力越强，参数越多 | 8~64 |
| `lora_alpha` | 缩放因子，通常等于 r 或 2r | 16~128 |
| `target_modules` | 在哪些层加 LoRA | 从 `q_proj, v_proj` 起步，或全部 attention+MLP |
| `lora_dropout` | 防过拟合 | 0.05~0.1 |

### QLoRA（Quantized LoRA）

LoRA 减少了可训练参数，但基础权重（冻结部分）仍需加载进显存：7B 模型 BF16 需要 14GB，70B 需要 140GB。

QLoRA 将冻结的基础权重量化为 **4-bit**（NF4 格式），仅用约 4GB 存储 7B 模型，然后在 4-bit 基础上做 LoRA 训练。

**核心技术：**
- **NF4（NormalFloat4）：** 专为正态分布神经网络权重设计的 4-bit 格式，比普通 INT4 精度更高
- **双重量化（Double Quantization）：** 对量化参数（scale 和 zero-point）再量化一次，进一步节省内存
- **分页优化器（Paged Optimizer）：** 用 NVIDIA 统一内存，防止 OOM 时直接崩溃

**显存需求对比：**

| 模型 | 全参数微调 | LoRA（BF16） | QLoRA（4-bit） |
|------|-----------|-------------|--------------|
| 7B | ~60GB | ~20GB | **~10GB** |
| 13B | ~120GB | ~40GB | **~18GB** |
| 70B | 500GB+ | ~180GB | **~48GB** |

24GB 消费级 GPU（RTX 3090/4090）可以用 QLoRA 微调 13B 模型，多卡可做 70B。

### DoRA（Weight-Decomposed Low-Rank Adaptation）

将权重矩阵 `W` 分解为方向和幅度两个分量，方向用 LoRA 低秩矩阵更新，幅度单独学习。实验表明 DoRA 在许多任务上（尤其指令跟随）效果优于同参数量的 LoRA。

### Prefix Tuning

在输入序列前加一段可学习的"软提示词"（soft prompts），通常为 10-100 个虚拟 token。这些 token 不对应真实词汇，其 embedding 在微调过程中学习得出。原始模型参数完全冻结，只训练前缀 embedding。

## 6.3 指令微调（SFT）

监督微调（Supervised Fine-Tuning, SFT）是将预训练基座改造为对话助手的关键步骤。

### 数据格式（Chat Template）

现代对话模型使用结构化 Chat Template：

```
<|begin_of_text|>
<|start_header_id|>system<|end_header_id|>
你是一个有帮助的 AI 助手。<|eot_id|>

<|start_header_id|>user<|end_header_id|>
请解释量子纠缠是什么？<|eot_id|>

<|start_header_id|>assistant<|end_header_id|>
量子纠缠是指两个粒子在某种方式上相互关联...<|eot_id|>
```

关键设计：
- **只对 Assistant 部分计算 Loss**（System 和 User 部分 mask 掉）
- 使用特殊 token 标记对话轮次边界
- 多轮对话拼接成长序列，提高训练效率

### 数据质量 > 数据量

LIMA 论文（Meta AI, 2023）发现：仅用 **1000 条精心挑选的高质量指令数据**微调 65B LLaMA，在人工评估中可媲美数万条数据训练的模型。

高质量数据的标准：
1. **多样性：** 覆盖不同任务类型（写作、推理、代码、问答）
2. **准确性：** 答案正确，无事实错误
3. **格式规范：** 回答风格统一、不啰嗦
4. **难度适中：** 太简单学不到东西，太难模型学不会

### 多任务混合比例

| 任务类型 | 典型占比 | 说明 |
|---------|---------|------|
| 通用对话与问答 | 30-40% | 保持通用能力 |
| 推理与数学 | 15-20% | 提升逻辑能力 |
| 代码 | 10-20% | 编程能力 |
| 写作与创作 | 10-15% | 写作风格 |
| 安全与拒绝 | 3-5% | 让模型学会拒绝有害请求 |

## 6.4 实践选型建议

### 消费级 GPU（24GB）：QLoRA 微调 7B/13B

**7B 模型完整配置参考：**

```python
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
from peft import get_peft_model, LoraConfig, TaskType

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_use_double_quant=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16
)

lora_config = LoraConfig(
    task_type=TaskType.CAUSAL_LM,
    r=16,
    lora_alpha=32,
    target_modules=[
        "q_proj", "k_proj", "v_proj", "o_proj",
        "gate_proj", "up_proj", "down_proj"
    ],
    lora_dropout=0.05,
    bias="none"
)

training_args = TrainingArguments(
    per_device_train_batch_size=2,
    gradient_accumulation_steps=8,   # 等效 batch=16
    num_train_epochs=3,
    learning_rate=2e-4,
    bf16=True,
    gradient_checkpointing=True,
    warmup_ratio=0.03,
    lr_scheduler_type="cosine",
    max_grad_norm=1.0,
    weight_decay=0.001,
)
```

**显存占用预估（7B QLoRA）：**
- 模型权重（4-bit）：~4GB
- LoRA 参数（BF16）：~0.5GB
- 激活值 + 梯度：~6GB
- 优化器状态：~2GB
- **合计：~12-14GB**，24GB 显卡充裕

### 数据量与策略匹配

| 数据量 | 推荐策略 | 注意事项 |
|--------|---------|--------|
| **<100 条** | Prompt Engineering / Few-shot | 数据太少，微调容易过拟合 |
| **100-1000 条** | QLoRA，低 r 值（4-8），低 epoch（1-2） | 务必用高质量数据 |
| **1K-10K 条** | LoRA（r=8~16）或 QLoRA | 效果通常很好 |
| **10K-100K 条** | LoRA（r=16~64）或全参数微调 | 可增大 r 或全参微调 |
| **>100K 条** | 全参数微调 + 混入通用数据防遗忘 | 注意数据质量，警惕灾难性遗忘 |

### 微调效果评估

- 不要只看训练 Loss：训练 Loss 低不等于效果好，必须在 held-out 集上评估
- 定性评估必不可少：每训练完一个 checkpoint，手动测试 20-50 个典型问题
- 警惕格式问题：回答格式不对，通常是 Chat Template 配置错误或数据格式不一致
- 多轮对话验证：SFT 后单轮问答好，不代表多轮对话正常

# 七、对齐训练（Alignment）

预训练完成的模型的优化目标是"预测下一个 token"，这让它学会了语言规律，但也带来了问题：不会遵从指令、可能生成有害内容、语言流畅但内容不实。对齐训练将预训练模型改造为真正有用的助手。

---

## 7.1 对齐目标：3H 原则

对齐的目标通常用"3H"来描述：
- **Helpful（有用）**：真正帮助用户完成任务
- **Harmless（无害）**：不生成暴力、歧视、违法等有害内容
- **Honest（诚实）**：不编造虚假信息，不确定时承认不知道

三者之间存在张力——过度强调"无害"会让模型变得过度拒绝，失去有用性；过度强调"有用"又可能放开有害内容。如何平衡是对齐工程的核心难题。

---

## 7.2 RLHF 完整流程

RLHF（Reinforcement Learning from Human Feedback）是 InstructGPT、ChatGPT 使用的对齐方案，分三个阶段：

### 第一阶段：SFT（监督微调）

收集数千到数万条"提示 + 高质量回答"的配对数据，用监督微调让模型学会基本的指令跟随行为。这一阶段建立模型的基础指令能力，但还不足以让它在各种情况下都表现良好。

### 第二阶段：RM（奖励模型训练）

对同一个问题，让 SFT 模型生成多个不同回答，然后让人工标注者对这些回答进行排序。奖励模型（RM）基于这些排序数据训练，学会给任意回答打分：输入"问题 + 回答"，输出标量分数。

**RM 是 RLHF 最昂贵的部分**：需要大量人工排序标注（通常数万到数十万条），RM 质量直接决定最终模型的对齐质量。

### 第三阶段：PPO（强化学习优化）

PPO（Proximal Policy Optimization）利用 RM 的打分作为奖励信号，迭代优化模型：

1. 从提示数据集中采样一个问题
2. 当前模型（策略）生成一个回答
3. RM 给这个回答打分
4. PPO 根据奖励更新模型参数，鼓励高分行为

同时加入 **KL 散度惩罚**，防止模型为骗取高分而产生 Reward Hacking（生成奇怪但能高分的内容）。

**各阶段成本对比：**

| 阶段 | 数据需求 | 工程复杂度 | 主要挑战 |
|------|---------|-----------|--------|
| SFT | 数千~数万条标注对话 | 低 | 数据质量 |
| RM 训练 | 数万~数十万条排序数据 | 中 | 标注成本高 |
| PPO | 无需新标注，但需稳定训练 | 高 | 超参数敏感、训练不稳定 |

---

## 7.3 RLHF 替代方案对比

### DPO（Direct Preference Optimization）

不需要单独训练奖励模型，直接从偏好数据中学习。DPO 的核心洞察：RLHF 中奖励模型和策略更新可以合并成一个单一训练目标，数学上可以证明两者等价。

- 数据格式：三元组 `(prompt, chosen, rejected)`
- 优势：不需要强化学习、不需要奖励模型、训练稳定
- 适用：通用对话对齐

### GRPO（Group Relative Policy Optimization）

DeepSeek-R1 使用的方案。不用人工偏好数据，而是用规则判断对错——对数学题，答案对了给高分，错了给低分。

- 优势：规则奖励客观无偏，特别适合有明确对错的任务（数学、代码、逻辑推理），训练稳定
- 适用：推理能力对齐

### SimPO（Simple Preference Optimization）

去掉参考模型，直接对 chosen 和 rejected 的序列平均对数概率做 margin 优化。实现最简，训练最稳定，效果接近 DPO。

### 方案综合对比

| 方法 | 是否需要 RM | 训练稳定性 | 效果 | 适用场景 |
|------|------------|-----------|------|---------|
| **PPO（RLHF）** | 是 | 较难调 | 最强 | 资源充足、追求极致 |
| **DPO** | 否 | 稳定 | 接近 PPO | 通用对话对齐 |
| **GRPO** | 否（规则奖励）| 稳定 | 推理任务强 | 数学、代码、推理 |
| **SimPO** | 否 | 最稳定 | 良好 | 资源受限、快速对齐 |

---

## 7.4 推理能力对齐（新范式）

2024-2025 年出现了全新对齐范式：通过训练让模型在回答前深度思考，代表工作是 OpenAI o1 和 DeepSeek-R1。

### DeepSeek-R1 方案：GRPO + 规则奖励

1. 用数学、代码等有明确答案的题目训练
2. 奖励函数：答案正确 → 正奖励；格式正确（有 `<think>` 标签）→ 正奖励；答案错误 → 负奖励
3. 使用 GRPO：对同一问题生成多个回答，以组内相对排名作为奖励信号

结果：模型自发学会了"思考"——在 `<think>` 标签内写推理过程、尝试多种方法、自我纠错。这种思维链行为完全从强化学习中涌现，没有人工标注的思维链数据。

实践上，纯粹从 GRPO 冷启动效果不稳定，DeepSeek-R1 的实际做法是：

1. **冷启动：** 收集少量长思维链数据（Long CoT），先做 SFT 让模型学会思考的基本格式
2. **GRPO 强化：** 在 SFT 基础上用 GRPO 进一步强化推理能力
3. **蒸馏：** 将大模型（671B）的思维链蒸馏到小模型（7B/14B）

### Test-Time Compute 扩展

这种范式开辟了新的扩展维度：不仅可以用更多训练算力提升模型能力，推理时也可以投入更多算力（更长的思考链、更多的采样）来换取更高质量。

---

## 7.5 实践选型建议

| 场景 | 推荐方案 | 理由 |
|------|---------|------|
| **通用对话助手** | SFT + DPO | 最简可行路径，效果好，工程简单 |
| **数学/代码/推理增强** | SFT + GRPO（规则奖励）| 规则奖励客观准确，训练稳定 |
| **资源充足、追求极致** | 完整 RLHF（SFT + RM + PPO）| 效果最好，但工程成本高 |
| **快速验证** | SFT + SimPO | 最简单，适合快速迭代 |

**DPO 数据构造建议：**
- chosen：使用 GPT-4 或人工标注的高质量回答
- rejected：使用当前模型自身的输出，或质量明显低的回答
- 每个 prompt 对应 1 个 chosen + 1 个 rejected 即可
- 数据量：通常 5K-50K 条即可取得显著效果

# 八、量化与压缩

训练好的模型动辄数十 GB，直接部署成本极高。量化与压缩的目标是在尽量不损失模型能力的前提下，大幅减小模型体积和推理计算量。

---

## 8.1 量化基础

量化将神经网络权重从 FP32（32位）或 BF16（16位）压缩到更少位数（INT8、INT4），从而：
- 模型体积减小 2-8 倍
- 推理速度提升（低精度整数运算更快）
- 显存占用大幅降低

### PTQ vs QAT

**PTQ（Post-Training Quantization，训练后量化）：** 模型训练完成后直接对权重量化，不需要重训。速度快，无需大量数据，但精度损失相对较大。

**QAT（Quantization-Aware Training，量化感知训练）：** 训练过程中模拟量化的影响，让模型提前适应低精度环境。精度损失更小，但需要重新训练，成本高。

### 量化粒度

| 粒度 | 说明 | 精度损失 | 压缩效果 |
|------|------|---------|---------|
| **Per-tensor** | 整个张量用一组量化参数 | 最大 | 最好 |
| **Per-channel** | 每个输出通道独立量化 | 中等 | 中等 |
| **Per-group** | 每组（如128个元素）独立量化 | 最小 | 相对较大 |

现代量化方案（GPTQ、AWQ）通常使用 Per-group 量化，在精度和压缩率之间取得最佳平衡。

---

## 8.2 主流量化方案

### GPTQ

逐层量化，最小化量化前后每层输出的误差。通过 Hessian 矩阵指导哪些权重更重要，给予更精细的量化处理。

- **优点：** 精度损失较小，支持 INT4/INT3 极低比特
- **缺点：** 量化速度慢（大模型需要数小时）

### AWQ（Activation-aware Weight Quantization）

核心洞察：不是所有权重都同等重要。对应激活值较大的权重通道（"显著权重"），量化误差影响更大，应该优先保护，给予更高精度；其他权重可以更激进地压缩。

- **优点：** 精度损失比 GPTQ 更小，量化速度快（分钟级）
- **应用：** 目前最广泛使用的 INT4 量化方案之一

### GGUF（llama.cpp 格式）

llama.cpp 是专为 CPU 和消费级硬件推理设计的框架，GGUF 是其模型格式。

社区流行原因：
- 支持纯 CPU 推理，不需要 GPU
- 支持混合精度（部分层用更高精度）
- 跨平台（Windows/Mac/Linux）
- 配合 Ollama 等工具极易部署

**常用量化级别：**

| 格式 | 平均位宽 | 7B 模型大小 | 质量损失 |
|------|---------|-----------|--------|
| Q8_0 | 8-bit | ~8GB | 极小 |
| Q5_K_M | 5-bit | ~5GB | 很小 |
| **Q4_K_M** | **4-bit** | **~4GB** | **小（推荐）** |
| Q3_K_M | 3-bit | ~3GB | 中等 |
| Q2_K | 2-bit | ~2.5GB | 较大 |

Q4_K_M 是端侧部署的最佳平衡点：4GB 内存即可运行 7B 模型，质量损失可接受。

---

## 8.3 知识蒸馏

知识蒸馏让小模型（学生）不只学大模型（教师）的最终答案，还学教师输出的概率分布（软标签）。

软标签包含教师对各选项的置信度信息，比直接学答案包含更多知识。例如对"巴黎是哪个国家的首都"：
- 硬标签：法国=1，其他=0
- 软标签：法国=0.95，欧洲其他国家=0.03，美国=0.01……

### 黑盒蒸馏 vs 白盒蒸馏

**黑盒蒸馏：** 只能访问教师模型的最终输出（如 API），用这些输出作为学生的训练数据。典型做法：调用 GPT-4 生成高质量回答，用于微调小模型（Alpaca、WizardLM 的思路）。

**白盒蒸馏：** 能访问教师模型的内部状态（logits、中间层激活值），让学生不仅学输出，还学中间表示。
- **Logit 蒸馏：** 学生的 logits 分布尽量匹配教师的 logits 分布（KL 散度损失）
- **特征蒸馏：** 学生的中间层特征尽量匹配教师对应层的特征

白盒蒸馏效果更好，但需要访问教师模型权重（开源模型可用，商业 API 不可用）。

### 蒸馏 vs 小模型直接训练

| 方案 | 数据需求 | 效果 | 成本 |
|------|---------|------|------|
| **小模型直接预训练** | 需要大量原始数据 | 受限于训练数据质量 | 计算成本高 |
| **大模型蒸馏到小模型** | 需要大模型生成的数据 | 通常优于同等参数量直接训练 | 大模型推理成本 |

DeepSeek-R1 的蒸馏实验证明：用 671B 模型的思维链数据蒸馏出的 7B 模型，在数学推理上远超同等参数量直接训练的模型。

---

## 8.4 实践选型建议

| 场景 | 推荐方案 | 说明 |
|------|---------|------|
| **在线服务推理加速** | AWQ INT4 | 精度损失最小，推理速度提升 2-4x |
| **端侧/本地部署** | GGUF Q4_K_M | 4GB 显存运行 7B，llama.cpp/Ollama 生态 |
| **显存受限下的微调** | QLoRA（NF4）| 量化 + 高效微调一体化 |
| **追求最高精度** | GPTQ INT8 | 精度损失极小，但体积只压缩一半 |
| **有教师模型资源** | 知识蒸馏 | 小模型效果可超越同参数直接训练 |
