## 第一章：在 Transformer 之前——模型是怎么"读"语言的？

### 一、机器读语言，难在哪里？

我们先想一个问题：语言为什么难处理？

数字、图片对计算机来说都相对好处理——数字本身就是数，图片是像素矩阵。但语言不一样，语言有一个其他数据没有的特性：

> **词的意思，依赖它出现的位置和上下文。**

同样一个"苹果"，出现在"我吃了一个苹果"和"苹果发布了新手机"里，意思完全不同。同样一个"他"，可能指的是三句话之前出现的某个人。

这意味着机器要理解语言，必须有某种方式处理**序列**——不仅要知道每个词是什么，还要知道词和词之间的关系、前后的依赖。

早期的研究者想到的第一个方案，是模仿人类读书的方式：**一个词一个词，按顺序读。**

---

### 二、RNN：像人一样"顺序阅读"

#### 核心思路

RNN（循环神经网络-Recurrent Neural Network）的设计理念非常直觉：既然语言是有顺序的，那就按顺序处理，读完每个词之后，把"读到这里的理解"传递给下一步。

这个"理解"有个专门的名字，叫**隐藏状态（Hidden State）**，可以把它想象成一张便条纸——读完每个词之后，在便条上更新一下当前的理解，然后带着这张便条继续读下一个词。

```
输入：  我    爱    北    京    天    安    门
        ↓     ↓     ↓     ↓     ↓     ↓     ↓
RNN:  [h1] → [h2] → [h3] → [h4] → [h5] → [h6] → [h7]
                                                     ↓
                                               最终理解
```

每一步都把上一步的隐藏状态带进来，读完整个句子后，最后那个隐藏状态理论上包含了整句话的信息。

#### RNN 的问题：记忆会"消失"

听起来很合理，但实际用起来有个致命问题：**便条纸太小了，写不下太多东西。**

更准确地说，RNN 在传递隐藏状态的过程中，**早期的信息会被不断稀释**。读到第100个词的时候，第1个词的信息已经在经历了99次更新之后，几乎消失殆尽了。

这个问题叫做**梯度消失**，用直觉来理解：

> 想象你在玩"传话游戏"——第一个人说一句话，每个人听完之后转述给下一个人。传到第20个人的时候，原话通常已经面目全非。

RNN 处理长句子就是这种情况。

```
"虽然他小时候家境贫寒，但经过多年努力，他最终......"

RNN 读到"最终"的时候：
- "他" ✅ 还记得
- "努力" ✅ 还记得
- "小时候" ⚠️ 有点模糊
- "家境贫寒" ❌ 几乎忘了
```

---

### 三、LSTM：给 RNN 装上"长期记忆"

#### 核心思路

为了解决 RNN 的遗忘问题，研究者在1997年提出了 LSTM（长短期记忆网络-Long Short-Term Memory）。

LSTM 的改进思路很聪明：**与其用一张便条纸，不如同时用两条通道——一条记短期的，一条记长期的。**

可以用一个更形象的比喻：

> 想象你在读一本很长的侦探小说。你有两样东西：
> - 一个**工作台**：放着你现在正在分析的线索（短期记忆）
> - 一个**档案柜**：存着整个案件的关键信息（长期记忆）
>
> 读到新内容时，你会决定：
> 1. 哪些新信息值得存进档案柜？（输入门）
> 2. 档案柜里哪些旧信息可以丢掉了？（遗忘门）
> 3. 现在该从档案柜里取出什么？（输出门）

```
        遗忘门         输入门         输出门
          ↓              ↓              ↓
长期记忆: [====旧信息====] → [=旧+新信息=] → 输出当前理解
                              ↑
                         短期记忆 + 当前输入
```

LSTM 确实比 RNN 强很多，能记住更长距离的依赖。一度成为处理文本、语音的标准方案。

#### LSTM 还是没解决的问题

但 LSTM 有两个根本性的局限：

**第一个：还是得按顺序读。**

不管 RNN 还是 LSTM，都必须读完第1个词才能读第2个，读完第2个才能读第3个。这意味着整个过程**无法并行**——在 GPU 这种专门为并行计算设计的硬件上，效率极低。

训练一个大模型，要处理海量文本，如果每句话都得一个词一个词串行处理，时间成本是灾难性的。

**第二个：长距离依赖还是很难。**

虽然 LSTM 比 RNN 好，但几百个词之外的信息依然很难保留。而真实的语言里，长距离依赖非常普遍：

```
"这家餐厅的装修很有特色，服务也很好，菜品种类丰富，
 价格也算合理，唯一的缺点就是停车场太小，
 不过总体来说，我还是很推荐___"

这里的"推荐"，关联的是前面整段话的综合评价。
LSTM 在这么长的距离上，表现已经开始吃力。
```

---

### 四、Seq2Seq：让机器学会"翻译"

#### 核心思路

大概在2014年前后，研究者把 RNN/LSTM 组合成了一个新框架，叫 **Seq2Seq（序列到序列）**。这个框架的出现，第一次让机器翻译的效果有了质的飞跃。

设计思路很直观：

> 找两个 LSTM，一个负责"读"（Encoder），一个负责"写"（Decoder）。
> - Encoder 把整段原文压缩成一个向量（叫做**语义向量**或 **Context Vector**）
> - Decoder 拿着这个向量，逐词生成译文

```
原文：  I   love   Beijing
         ↓    ↓      ↓
Encoder: 读完整段，压缩成一个向量 → [    C    ]
                                          ↓
Decoder:                            我 → 爱 → 北京
```

这个框架奠定了"编码-解码"的基本思路，后来 Transformer 的 Encoder-Decoder 结构直接继承了这个理念。

#### Seq2Seq 的瓶颈：一个向量装不下所有信息

Seq2Seq 有个致命缺陷：**整段原文被强行压缩成一个固定大小的向量。**

想象一下，你要把《红楼梦》的内容压缩成一张名片大小的纸，再让另一个人根据这张名片复述原著。信息损失是必然的。

句子越长，这个问题越严重。翻译长句子时，Seq2Seq 的效果会急剧下降。

---

### 五、Attention：一个改变一切的"补丁"

#### 问题的本质

Seq2Seq 的核心问题是：Decoder 在生成每个词的时候，只能看那一个压缩向量，**不知道该重点参考原文的哪个部分**。

比如翻译"I love Beijing"：
- 生成"我"的时候，最该关注"I"
- 生成"爱"的时候，最该关注"love"
- 生成"北京"的时候，最该关注"Beijing"

但 Seq2Seq 的 Decoder 每次都只能看同一个压缩向量，无法做到这种"按需关注"。

#### Attention 的解法

2015年，Bahdanau 等人提出了 **Attention 机制**，思路极其优雅：

> **不要把原文压缩成一个向量，而是把每个词的信息都保留下来。Decoder 在生成每个词的时候，自己决定该重点看原文的哪些位置。**

```
原文编码：  [I的向量]  [love的向量]  [Beijing的向量]
                ↑           ↑              ↑
           权重:0.8      权重:0.1       权重:0.1
                \           |              /
                 \          |             /
Decoder生成"我"时，主要关注"I"，稍微瞄一眼其他词
```

这个"权重"就是注意力分数——Decoder 自动学习在生成每个词时，应该把多少注意力分配给原文的每个位置。

效果立竿见影，机器翻译的质量大幅提升，尤其是长句子。

#### Attention 为什么是转折点

Attention 刚出来的时候，只是 Seq2Seq 的一个增强模块，RNN 还在。但它揭示了一个深刻的道理：

> **语言理解的核心，是建立词与词之间的关联，而不是顺序处理。**

这个洞察，直接导致了两年后的关键一问：

**"如果 Attention 才是真正有效的部分，为什么还需要 RNN？"**

---

### 六、转折点：Attention is All You Need

2017年，Google 发表了一篇标题极其自信的论文：**《Attention is All You Need》**。

论文的核心主张只有一句话：

> **把 RNN 完全去掉，只用 Attention，效果更好，速度更快。**

这就是 **Transformer** 的诞生。

去掉 RNN 带来了什么？

```
RNN 时代：
词1 → 词2 → 词3 → 词4 → 词5    （必须串行，慢）

Transformer 时代：
词1 ↘
词2 → 所有词同时互相计算注意力   （完全并行，快）
词3 ↗
```

**并行计算**意味着可以把数据拆给成千上万张 GPU 同时处理，训练速度提升了数量级。这才让"用海量数据训练超大模型"变成了可能。

---

### 本章小结

```
时间线：

1980s  RNN 诞生
  └─ 问题：顺序处理、梯度消失、无法并行

1997   LSTM 诞生
  └─ 改进：更好的长期记忆
  └─ 问题：还是顺序处理、长距离依赖仍然吃力

2014   Seq2Seq 诞生
  └─ 改进：第一次实现端到端翻译
  └─ 问题：信息压缩瓶颈

2015   Attention 机制出现
  └─ 改进：按需关注，信息不再压缩丢失
  └─ 关键洞察：关联比顺序更重要

2017   Transformer 诞生
  └─ 改进：去掉 RNN，纯 Attention，完全并行
  └─ 影响：开启了大模型时代
```

## 第二章：Transformer 登场——"注意力就是一切"

### 一、Transformer 到底长什么样？

上一章说到，2017年 Google 提出了一个大胆的想法：**把 RNN 完全去掉，只用 Attention 机制来处理语言。**

但光有 Attention 还不够，Transformer 把它组织成了一套完整的架构。我们先从整体上看它长什么样。

Transformer 最初的设计是为了做翻译，所以它分成两个部分：

```
原文（英文）
    ↓
┌─────────────┐
│   Encoder   │  ← 负责"读懂"原文
│  （编码器）  │
└─────────────┘
    ↓ 把理解结果传过去
┌─────────────┐
│   Decoder   │  ← 负责"生成"译文
│  （解码器）  │
└─────────────┘
    ↓
译文（中文）
```

Encoder 和 Decoder 内部结构很相似，都是把若干层"注意力 + 前馈网络"叠在一起。层数越多，模型理解能力越强。

---

### 二、Self-Attention：每个词都在问"我该关注谁？"

Transformer 最核心的创新，是把 Attention 用在了**同一个句子内部**，叫做 **Self-Attention（自注意力）**。

之前的 Attention 是 Decoder 关注 Encoder 的输出。而 Self-Attention 是：**句子里的每个词，去关注同一句话里的其他所有词。**

用一个具体例子来感受：

> 句子："The animal didn't cross the street because it was too tired."
> 问题：**"it"指的是什么？**

对人类来说，"it"显然指的是"animal"而不是"street"。但机器怎么知道？

Self-Attention 的做法是：让"it"这个词去问句子里的每个词——"你和我的关联有多大？"

```
"it" 询问每个词的相关性：

The      → 0.02
animal   → 0.68  ← 关联最强
didn't   → 0.01
cross    → 0.03
the      → 0.01
street   → 0.08
because  → 0.05
it       → 0.04
was      → 0.03
too      → 0.02
tired    → 0.03
```

"it"发现自己和"animal"关联最强，于是在理解"it"的语义时，大量借用了"animal"的信息。这样模型就"知道"了 it 指的是 animal。

### Q、K、V：注意力机制的三个角色

Self-Attention 内部有三个概念，理解它们有助于后面讲 MLA 等架构创新。

每个词在计算注意力时，会同时扮演三个角色：

| 角色 | 全称 | 类比 |
|------|------|------|
| Q | Query（查询） | 我想找什么？ |
| K | Key（键） | 我能提供什么标签？ |
| V | Value（值） | 我实际包含的信息 |

用图书馆来类比：

```
你去图书馆找书（Query）
书架上每本书都有索引标签（Key）
你根据标签找到相关书，然后阅读内容（Value）

Q 和 K 决定"该关注谁"
V 是真正被读取的信息
```

每个词都会生成自己的 Q、K、V 三个向量。计算注意力时：
- 用自己的 Q 和所有词的 K 比较，得出注意力分数（关注程度）
- 再用这个分数对所有词的 V 加权求和，得到自己更新后的表示

这个过程每个词同时进行，完全并行。

---

### 三、Multi-Head Attention：从多个角度同时看

只用一组 Q、K、V 计算注意力，视角是单一的。Transformer 进一步提出了 **Multi-Head Attention（多头注意力）**。

思路很简单：**同时用多组 Q、K、V 并行计算，每组关注不同的语言特征，最后合并结果。**

```
同一句话，不同的"头"关注不同的事：

Head 1 → 关注语法结构（主谓宾关系）
Head 2 → 关注语义相似性（同义词、近义词）
Head 3 → 关注指代关系（it 指的是谁）
Head 4 → 关注位置关系（前后文距离）
...
Head N → ...

最终把所有头的结果拼在一起 → 更丰富的理解
```

就像看一幅画，有人关注色彩，有人关注构图，有人关注笔触，综合所有人的观察，理解才更全面。

---

### 四、位置编码：告诉模型"词的顺序"

Self-Attention 有个副作用：它让所有词同时互相关注，**完全不在乎顺序**。

但语言的顺序显然很重要：

```
"猫追狗" 和 "狗追猫" ← 词相同，意思相反
```

怎么办？Transformer 的解法是在输入阶段直接给每个词加上**位置编码（Positional Encoding）**——在词的向量里注入位置信息，告诉模型"这个词在第几位"。

```
输入 = 词的语义向量 + 位置编码向量

"猫"在第1位 → 猫的向量 + 位置1的编码
"追"在第2位 → 追的向量 + 位置2的编码
"狗"在第3位 → 狗的向量 + 位置3的编码
```

这样模型在做 Self-Attention 时，既知道词的语义，也知道它在句子中的位置。

位置编码后来成为了一个重要的演进方向——从最初的固定公式，到后来的 RoPE（旋转位置编码），这个问题一直在被优化，第六章会专门讲。

---

### 五、前馈网络：注意力之后做什么

每一层 Transformer 里，除了 Self-Attention，还有一个**前馈网络（Feed-Forward Network，FFN）**。

如果说 Self-Attention 负责"词与词之间的信息交换"，那 FFN 负责的是"每个词独立深化自己的理解"。

```
Self-Attention：
词1 ←→ 词2 ←→ 词3  （词之间互相交流）
 ↓       ↓      ↓
FFN：
词1     词2     词3  （每个词各自深化理解，互不干扰）
```

FFN 占了 Transformer 参数量的大头（大约2/3），后来 MoE 架构的改造，主要就是针对 FFN 这部分做的——这是第五章的内容。

---

### 六、Encoder 和 Decoder 的分工

现在可以说清楚 Encoder 和 Decoder 各自做什么了。

**Encoder（编码器）**

- 输入：原文所有词
- 每个词做 Self-Attention：可以同时看左边和右边（双向）
- 输出：每个词的深度语义表示
- 比喻：像一个精读原文的翻译官，把每句话都理解透彻

```
双向 Self-Attention：
← 我 爱 北京 天安门 →
每个词可以看前面也可以看后面
```

**Decoder（解码器）**

- 输入：已经生成的译文词（逐步增加）
- 做两种注意力：
  1. **Masked Self-Attention**：只能看自己左边已生成的词（不能"偷看"未来）
  2. **Cross-Attention**：关注 Encoder 的输出（参考原文）
- 输出：下一个词的预测
- 比喻：像一个正在下笔的翻译官，一边参考原文，一边确保译文前后一致

```
Decoder 生成第3个词时：

已生成：我 爱 ___

Masked Self-Attention：只看"我"和"爱"，不看后面
Cross-Attention：参考 Encoder 对原文的理解
→ 预测下一个词："北京"
```

---

### 七、为什么 Transformer 如此成功？

把上面所有东西放在一起，Transformer 的核心优势变得清晰：

```
┌─────────────────────────────────────────────────────┐
│                  Transformer 的优势                  │
├──────────────┬──────────────────────────────────────┤
│ 并行计算     │ 所有词同时处理，GPU 利用率极高          │
│ 长距离依赖   │ 任意两个词直接建立关联，不经过中间传递   │
│ 可扩展性     │ 堆叠更多层、更多头，效果持续提升         │
│ 通用性       │ 同一套架构，用于翻译、分类、生成         │
└──────────────┴──────────────────────────────────────┘
```

对比之前的方案：

```
             顺序处理   长距离依赖   并行训练   扩展性
RNN            ✅          ❌          ❌        ❌
LSTM           ✅          ⚠️          ❌        ⚠️
Transformer    ❌(无顺序)  ✅          ✅        ✅
```

（"无顺序"不是缺点，位置编码补上了这一点）

```
Transformer 的核心组件：

输入
 ↓
词向量 + 位置编码          ← 知道词是什么、在哪里
 ↓
Multi-Head Self-Attention  ← 词与词之间建立关联（多角度）
 ↓
前馈网络（FFN）            ← 每个词深化自己的理解
 ↓
（重复 N 层）
 ↓
输出

Encoder = 双向 Attention，负责理解
Decoder = 单向 Attention + Cross-Attention，负责生成
```

Transformer 解决了 RNN 的并行问题和长距离依赖问题，但此时它还只是个翻译工具。

**下一章的问题是：同样是 Transformer，OpenAI 和 Google 为什么走向了两条完全不同的路？**

---

## 第三章：GPT vs BERT——两条路的分叉

### 一、同一个 Transformer，两种截然不同的用法

2017年 Transformer 诞生之后，整个 AI 界都意识到这个架构有巨大潜力。但问题来了：**怎么用它？**

Transformer 有 Encoder 和 Decoder 两个部分。理论上可以：
- 只用 Encoder
- 只用 Decoder
- 两个都用

2018年前后，两个最重要的团队给出了两个不同的答案：

- **Google** 选择了只用 Encoder → 这就是 **BERT**
- **OpenAI** 选择了只用 Decoder → 这就是 **GPT**

两条路，两种哲学，两种截然不同的能力边界。理解这次分叉，是理解今天所有大模型架构选择的关键。

---

### 二、Google 的选择：BERT 和"完形填空"

#### 核心思路

Google 的团队在思考一个问题：**怎么让模型真正"理解"语言？**

他们的答案是：做完形填空。

具体来说，把一段文本里的某些词随机遮住（用 `[MASK]` 替代），让模型猜被遮住的词是什么。

```
原句：  今天 天气 很 好 ，我 想 去 公园 散步
遮掩后：今天 天气 很 [MASK] ，我 想 去 [MASK] 散步
模型猜：              好              公园
```

这个任务看起来简单，但要猜对，模型必须同时理解：
- 前面的上下文（"天气很"）
- 后面的上下文（"，我想去"）

这就要求模型具备**双向理解**能力——每个词不仅要看左边，也要看右边。

Encoder 天然支持双向注意力，正好适合这个任务。

这就是 **BERT（Bidirectional Encoder Representations from Transformers）**，2018年10月由 Google 发布。

#### BERT 擅长什么

双向理解带来的能力，在"分析已有文本"这类任务上非常强：

```
BERT 擅长的任务：

情感分析：  "这部电影真的太好看了" → 正面 ✅
文本分类：  新闻分类、垃圾邮件识别 ✅
命名实体：  "马云创立了阿里巴巴" → [人名][公司名] ✅
问答匹配：  问题和段落的相关性判断 ✅
搜索排序：  哪个文档和查询最相关 ✅
```

BERT 发布后横扫了几乎所有 NLP 评测榜单，被称为"NLP 的 ImageNet 时刻"——就像计算机视觉领域 ImageNet 数据集定义了图像理解的标准，BERT 重新定义了语言理解的标准。

#### BERT 的根本局限

但 BERT 有一个它无法克服的问题：**它只会"读"，不会"写"。**

Encoder 的双向注意力，意味着每个词在生成表示时，已经看到了整个句子——包括"未来"的词。这在理解任务里没问题，但在**生成任务**里是灾难性的：

```
生成任务的逻辑：
已知：今天天气___
生成：好

如果模型在生成"好"的时候，已经看到了后面的词，
那它不是在"预测"，而是在"抄答案"。
```

用 BERT 做文本生成，就像让一个只会批改作文的老师去写文章——他能分析好坏，但下笔就不行了。

---

### 三、OpenAI 的选择：GPT 和"猜下一个词"

#### 核心思路

OpenAI 的团队选择了一个看起来更"笨"的任务：**预测下一个词。**

给模型看一段文字，让它猜下一个词是什么。就这么简单。

```
输入：今天天气
预测：很

输入：今天天气很
预测：好

输入：今天天气很好，我
预测：想
```

这个任务用 Decoder 来做——因为 Decoder 的 Masked Self-Attention 保证了每个词只能看左边，不能"偷看"未来，完美契合"猜下一个词"的需求。

这就是 **GPT（Generative Pre-trained Transformer）**，2018年6月由 OpenAI 发布，比 BERT 早了4个月。

#### "猜下一个词"为什么能学会一切？

第一眼看，"猜下一个词"好像是个很浅的任务。但仔细想想：

> 要持续猜对下一个词，模型必须学会：
> - 语法（"我"后面更可能跟动词）
> - 常识（"太阳从东边"后面跟"升起"）
> - 逻辑（前提成立，结论才能成立）
> - 世界知识（"法国的首都"后面是"巴黎"）
> - 写作风格（学术文章和小说的下一个词分布不同）

换句话说，**要把"猜下一个词"这件事做好，模型必须隐式地理解人类积累的所有知识。**

这个洞察，配上"数据越多、模型越大、效果越好"的规律，就成了大模型时代的核心驱动力。

#### GPT-1、GPT-2、GPT-3：规模的力量

OpenAI 从 GPT-1 开始，就坚定地走"把模型做大"这条路：

```
版本      年份    参数量      关键发现
GPT-1     2018    1.17亿     证明预训练+微调范式可行
GPT-2     2019    15亿       大到 OpenAI 不敢开源（怕被滥用）
GPT-3     2020    1750亿     震惊世界，few-shot 能力出现
```

GPT-3 是真正的分水岭。在此之前，大家认为模型要完成具体任务，必须针对该任务收集数据、专门微调。

但 GPT-3 展示了一种新能力：**只给几个例子，甚至不给例子，直接用自然语言描述任务，模型就能完成。**

```
Few-shot 示例：

提示词：
把下面的句子翻译成法语：
"Hello" → "Bonjour"
"Goodbye" → "Au revoir"
"Thank you" → ___

GPT-3：Merci  ✅（正确）

模型没有专门训练过翻译，但它"懂"了任务的模式。
```

这种能力叫 **In-context Learning（上下文学习）**，是大模型最神奇的涌现能力之一。

---

### 四、两条路的能力对比

到这里可以清晰地比较两者：

```
              BERT（Encoder-only）    GPT（Decoder-only）
核心任务       完形填空               预测下一个词
注意力方向     双向（看全文）          单向（只看左边）
擅长           理解、分析、分类        生成、续写、对话
不擅长         生成文本               深度语义匹配（早期）
训练数据       有标注+无标注           纯无标注文本
代表应用       搜索、情感分析          写作、对话、推理
```

2018-2020年，两条路都有很多追随者：

```
BERT 系列：
- RoBERTa（Facebook，更好的训练方式）
- ALBERT（Google，更小的参数量）
- DistilBERT（Hugging Face，蒸馏压缩版）
- MacBERT、ERNIE（百度，中文优化）

GPT 系列：
- GPT-2（OpenAI）
- GPT-3（OpenAI）
- 早期 Megatron-LM（英伟达）
```

---

### 五、还有第三条路：Encoder-Decoder 全保留

除了 BERT 和 GPT，还有一批研究者选择把 Encoder 和 Decoder 都保留，代表是 Google 的 **T5** 和 Facebook 的 **BART**。

思路是：**把所有任务都统一成"输入一段文字，输出一段文字"的格式。**

```
T5 的任务格式：

翻译任务：
输入："translate English to French: Hello"
输出："Bonjour"

摘要任务：
输入："summarize: [一篇长文章]"
输出："[摘要]"

分类任务：
输入："sentiment: 这部电影太好看了"
输出："positive"
```

这个思路很优雅，统一了所有 NLP 任务的格式。T5 在很多任务上的效果也很好。

但它最终没有成为主流，原因在第四章会详细说——简单剧透：**结构越复杂，扩展起来越麻烦。**

---

### 六、转折点：ChatGPT 让一切尘埃落定

2022年11月，OpenAI 发布了 **ChatGPT**。

ChatGPT 的底层架构不是新东西——还是 GPT-3.5，还是 Decoder-only。但它加入了一个关键的训练步骤：**RLHF（基于人类反馈的强化学习）**。

简单说，就是让人类评价模型的回答好不好，然后用这个反馈继续训练模型，让它更符合人类的期望。

```
普通 GPT-3：给它一个提示词，它会续写，
            但不一定按你的意图来。

ChatGPT：   它学会了"对话"——理解你的意图，
            给出有用的、安全的、连贯的回答。
```

ChatGPT 两个月用户破亿，成为史上增长最快的消费级应用。

这件事的架构意义是：**它证明了 Decoder-only + 指令微调，是通往通用 AI 助手的正确路径。**

BERT 系的模型，无论理解能力多强，在这个新时代里都成了配角。所有顶级实验室，从这一刻起，几乎全部押注 Decoder-only。

---

### 本章小结

```
2018   BERT 发布（Google）
  └─ Encoder-only，双向理解，完形填空
  └─ 横扫理解类任务榜单

2018   GPT-1 发布（OpenAI）
  └─ Decoder-only，单向生成，预测下一词
  └─ 证明预训练范式可行

2019   GPT-2 发布
  └─ 扩大规模，生成质量惊人

2020   GPT-3 发布
  └─ 1750亿参数，few-shot 能力涌现
  └─ 规模定律（Scaling Law）被确立

2020   T5/BART 发布
  └─ Encoder-Decoder 全保留，统一任务格式
  └─ 效果好，但扩展性不如 Decoder-only

2022   ChatGPT 发布
  └─ RLHF 让模型真正"听话"
  └─ Decoder-only 一统江湖，其他架构退场
```

**两条路的竞争，以 Decoder-only 的全面胜利告终。**

## 第四章：Decoder-only 为何最终一统江湖

> **Decoder-only 为什么能赢？它的扩展性到底好在哪里？各家模型又是怎么在这个基础上各显神通的？**

### 一、先回答一个问题：T5 那么好，为什么输了？

上一章提到，Google 的 T5 把 Encoder 和 Decoder 都保留，任务格式统一优雅，效果也不差。那它为什么没赢？

答案要从一个关键规律说起——**Scaling Law（规模定律）**。

2020年，OpenAI 发表了一篇论文，得出了一个简单但影响深远的结论：

> **模型参数量越大、训练数据越多、计算量越大，模型效果就越好。而且这个关系是可预测的、持续的。**

这意味着：只要你有足够多的算力和数据，把模型做大，效果就会持续提升，没有明显的天花板。

这个发现直接定义了接下来几年的军备竞赛逻辑——**谁能把模型做得更大，谁就赢。**

在这个背景下，架构的扩展性变得至关重要。而这正是 Encoder-Decoder 的致命弱点。

---

### 二、Encoder-Decoder 扩展起来有多麻烦？

T5 的结构要维护两套参数：Encoder 一套，Decoder 一套。这带来了几个实际问题：

```
Encoder-Decoder 扩展的麻烦：

1. 参数分配难题
   - Encoder 给多少层？Decoder 给多少层？
   - 两边比例不对，效果就差
   - 没有一个通用的最优配比

2. 训练目标复杂
   - Encoder 要学"理解"
   - Decoder 要学"生成"
   - 两个目标同时优化，互相干扰

3. 推理时的额外开销
   - 每次生成都要先跑一遍 Encoder
   - 再跑 Decoder，还要做 Cross-Attention
   - 计算量和内存占用更高

4. 工程复杂度高
   - 两套参数意味着更复杂的分布式训练策略
   - 跨机器通信开销更大
```

相比之下，Decoder-only 的结构极其简洁：**只有一套参数，只有一个目标（预测下一个词），只有一种注意力（Masked Self-Attention）。**

想把它做大？直接加层、加宽就行，没有任何结构上的纠结。

```
Decoder-only 扩展：

7B → 13B → 30B → 70B → 405B

每一步只需要：
- 更多层（深度）
- 更宽的维度（宽度）
- 更多训练数据
- 更多 GPU

结构不变，规律一直成立。
```

这种简洁性，在"把模型做到极致大"这件事上，有着压倒性的优势。

---

### 三、"预测下一个词"是个万能任务

除了扩展性，Decoder-only 还有一个深层优势：**它的训练任务天然覆盖了所有能力。**

用 BERT 做完形填空，训练数据必须加工——你需要随机遮掉词，设计遮掩策略。这已经引入了额外的人工设计。

而 Decoder-only 的训练任务是：**给我一段文字，我猜下一个词。**

这个任务需要什么数据？**任何文字都可以。** 网页、书籍、代码、论文、对话记录——互联网上存在的一切文字，都可以直接拿来训练，不需要任何标注和加工。

```
训练数据来源对比：

BERT：
- 需要构造 [MASK] 样本
- 部分任务需要人工标注
- 数据处理有额外成本

Decoder-only：
- 任何原始文本直接用
- Common Crawl（整个互联网的爬虫）
- Wikipedia、GitHub、arXiv...
- 数据量理论上无限
```

数据无限 + 规模定律持续有效 = 效果上限极高。

---

### 四、一个结构，同时搞定理解和生成

早期很多人以为：没有双向注意力的 Decoder，理解能力一定不如 BERT。

GPT-3 打破了这个直觉。

原因在于：虽然 Decoder 的每个词只能看左边，但经过足够多的层和足够大的参数量，模型会学会**从上下文推断当前词的含义**。

比如：

```
句子："苹果发布了新款___，售价8999元。"

Decoder 读到"___"之前，
已经看到了"苹果发布了新款"，
完全可以推断出后面是"手机"或"电脑"。

不需要看右边，也能理解。
```

当模型足够大，这种"从左推右"的能力会变得非常强，足以在大多数理解任务上媲美双向模型。

而且 Decoder 还保留了生成能力——一套结构，既能理解，又能生成。这是 BERT 永远无法做到的。

---

### 五、开源浪潮：LLaMA 打开的潘多拉魔盒

2023年2月，Meta 发布了 **LLaMA**（Large Language Model Meta AI）。

这件事的意义不仅仅是"又一个大模型"。LLaMA 是真正意义上的**开源**——不只是公开了论文，而是放出了模型权重，任何人都可以下载、运行、修改。

```
LLaMA 发布前：

顶级大模型 = 少数几家公司的专属武器
GPT-4：OpenAI 严格管控
PaLM：Google 内部使用
Claude：Anthropic 商业部署

LLaMA 发布后：

任何人都可以在自己的机器上跑大模型
任何研究团队都可以在此基础上改进
全球社区开始爆发式贡献
```

LLaMA 的架构选择，直接定义了之后开源社区的标准：

```
LLaMA 的关键架构选择：

1. 纯 Decoder-only           ← 继承 GPT 路线
2. RoPE（旋转位置编码）       ← 替代原始的绝对位置编码
3. RMSNorm（简化的归一化）    ← 训练更稳定，速度更快
4. SwiGLU 激活函数            ← 比 ReLU 效果更好
5. Pre-norm 结构              ← 归一化放在注意力之前
```

这些选择后来被几乎所有开源模型沿用，成为事实上的行业标准。

---

### 六、群雄并起：各家模型的演进

LLaMA 之后，开源社区和各大公司相继跟进，但都在同一个 Decoder-only 基础上做改进：

**Meta：LLaMA 系列**

```
  └─ 更大词表（128K tokens）

LLaMA 3.3（2024.12）

```

**阿里：Qwen 系列**


**几个关键观察**

```
所有这些模型的共同点：

架构基础     全部 Decoder-only      ← 没有例外
位置编码     全部使用 RoPE          ← LLaMA 定下的标准
训练目标     全部预测下一个词        ← 没有改变
差异化方向   MoE / 注意力优化 / 推理能力 / 多模态
```

**Decoder-only 已经不是一个"选择"，而是一个"默认"。** 在这个基础上，各家的竞争转移到了更细节的层面。

### 七、Decoder-only 自身的问题

Decoder-only 赢得了这场架构战争，但它本身并不完美。随着模型越做越大、应用越来越复杂，几个新问题开始浮现：

```
问题一：参数越多，每次推理越贵
  → 671B 参数的模型，每生成一个词都要激活所有参数
  → 解决方案：MoE（第五章）

问题二：上下文越长，显存越爆
  → 注意力机制是 O(n²) 复杂度，序列长度翻倍，计算量翻四倍
  → 解决方案：KV Cache 优化、MLA（第六章）

问题三：模型大了，但不会"思考"
  → 再大的模型，也是一步出答案，没有推理过程
  → 解决方案：Reasoning 架构（第七章）

问题四：只能处理文字
  → 真实世界是多模态的
  → 解决方案：多模态融合（第八章）
```

这四个问题，正好对应了后面四章的内容。

---

### 本章小结

```
Decoder-only 胜出的三个核心原因：

1. 扩展性最好
   结构简单，加层加宽就行，没有额外设计负担

2. 数据利用率最高
   任何原始文本都能直接训练，数据来源无限

3. 一套结构搞定一切
```
