## 第九章：挑战者登场——Mamba 和 SSM 能否撼动 Transformer

### 一、Transformer 有没有根本性的缺陷？

前八章讲下来，Transformer 好像无所不能——效果好、扩展性强、能理解图片、能学会思考。

但它确实有一个根本性的数学缺陷，一直没有被解决：

> **Self-Attention 的计算复杂度是 O(n²)。**

这意味着什么？

```
序列长度翻倍 → 计算量变成 4 倍
序列长度 × 10 → 计算量变成 100 倍

具体感受：
处理 1K token：计算量 = 1
处理 4K token：计算量 = 16
处理 16K token：计算量 = 256
处理 128K token：计算量 = 16384

从 1K 扩展到 128K → 计算量涨了 16000 倍
```

第六章讲到的各种优化（GQA、MLA、Flash Attention），都是在**工程层面**缓解这个问题，但没有改变 O(n²) 的本质。

这就是为什么一直有人在寻找 Transformer 的替代方案——能不能用**线性复杂度 O(n)** 的架构，在效果不输的前提下，处理更长的序列？

---

### 二、什么是状态空间模型（SSM）？

在理解 Mamba 之前，先要理解它的前身：**SSM（State Space Model，状态空间模型）**。

SSM 的灵感来自控制论，是一种描述动态系统的数学工具。

用一个非常直觉的比喻来理解：

```
Transformer 的处理方式（全局注意力）：

读一篇文章时，每读一个新词，
都要回头看整篇文章的每一个词，
然后决定对哪些词分配注意力。

→ 读到第 N 个词，需要看 N次 → O(n²)
```

```
SSM 的处理方式（状态压缩）：

读一篇文章时，维护一个"状态"（有点像 RNN 的隐藏状态），
每读一个新词，只更新这个状态，
不需要回头看所有词。

→ 读到第 N 个词，只需要看"状态" → O(n)
```

本质上，SSM 是在问：**能不能用一个"压缩摘要"代替"全文回顾"，同时不损失太多信息？**

早期的 SSM（比如 S4、H3）理论上很美好，但实际效果和 Transformer 差距较大，没有引起太多关注。

---

### 三、Mamba：SSM 的真正突破

2023年12月，Albert Gu 和 Tri Dao 发布了 **Mamba**，这是 SSM 历史上第一次在语言任务上正面挑战 Transformer。

Mamba 的核心创新叫做**选择性状态空间（Selective State Space）**：

```
传统 SSM 的问题：
状态更新的方式是固定的，对所有输入用同样的规则
→ 不管什么内容，处理方式一样
→ 重要信息和无关信息同等对待
→ 效果差

Mamba 的改进：
让状态更新的方式依赖于输入内容本身
→ 遇到重要内容：仔细更新，多保留
→ 遇到无关内容：快速掠过，少保留

用一个比喻：
传统 SSM 像一个笔记速度固定的学生，
不管老师讲什么，都用同样的速度记录。
Mamba 像一个聪明的学生，
老师讲重点时认真记，讲废话时跳过。
```

这个看似简单的改变，让 Mamba 的效果大幅提升：

```
Mamba 论文里的对比数据：

在语言建模任务上，相同参数量下：
- Mamba 效果接近甚至超过同规模 Transformer
- 序列长度越长，Mamba 的速度优势越大

速度对比（序列长度 2K vs 16K）：
Transformer：速度下降约 16 倍（因为 O(n²)）
Mamba：速度下降约 8 倍（接近线性）
```

---

### 四、Mamba 在哪些场景真的更好？

Mamba 不是在所有任务上都比 Transformer 强，它有自己的优势区间：

**Mamba 的优势场景：**

```
超长序列处理：
  DNA 序列分析（几十万碱基对）
  长音频信号处理
  时序数据预测
  → 序列越长，Mamba 的线性复杂度优势越明显

推理速度：
  生成文字时，Mamba 不需要维护 KV Cache
  → 显存占用更小
  → 生成速度更快（尤其是长序列）

内存效率：
  状态大小固定，不随序列长度增长
  → 100 token 和 100K token 的状态一样大
  → 对内存极友好
```

**Mamba 的劣势场景：**

```
In-context Learning（上下文学习）：
  GPT-3 展示的"给几个例子就能理解任务"的能力
  Mamba 明显弱于 Transformer
  → 因为状态压缩会丢失具体例子的细节

精确信息检索：
  "第 3 段第 2 句说了什么？"
  Transformer：直接通过注意力定位到那句话
  Mamba：信息已经被压缩进状态，精确提取困难

多步推理：
  需要精确引用上文具体信息来推理
  Mamba 的状态压缩容易丢失关键细节
```

### 五、混合架构：Mamba + Transformer

既然 Mamba 和 Transformer 各有优劣，一个自然的想法是：**把两者结合起来，取长补短。**

#### Jamba（AI21 Labs，2024）

> **Jamba** 是以色列 AI 公司 AI21 Labs 推出的混合架构模型，名称来自 **Ja**mba = **M**amba + Trans**f**ormer 的组合，核心思路是把两种层交替堆叠：多数层用 Mamba 保证长序列处理效率，少数层插入 Transformer 补充精确注意力能力。

```
Jamba 的结构：

交替排列 Transformer 层 和 Mamba 层：

层 1：Mamba 层    → 高效处理长序列
层 2：Mamba 层    → 高效处理长序列
层 3：Transformer 层 → 补充精确注意力能力
层 4：Mamba 层
...

每 N 个 Mamba 层插入 1 个 Transformer 层

效果：
- 长序列处理速度接近纯 Mamba
- In-context Learning 能力接近纯 Transformer
- 256K 上下文，单卡可运行
```

#### Zamba（Zyphra，2024）

> **Zamba** 是初创公司 Zyphra 推出的轻量混合架构模型，比 Jamba 更激进：绝大多数层用 Mamba，只设极少数"共享 Transformer 层"（所有 Mamba 层共用同一组 Transformer 参数而非每层单独一个），以此在极低参数量下保住 Transformer 的理解能力，主打小模型高效部署场景。

```
Zamba 的设计更极端：

大部分层用 Mamba
极少数"共享"的 Transformer 层（所有 Mamba 层共用）

→ 参数效率更高
→ 在小模型（7B）上表现出色
```

#### RWKV：RNN 的现代复活

> **RWKV**（发音同"RWaKuV"）是一个开源项目，名称来自其核心机制中四个关键向量的首字母：**R**eceptance、**W**eight、**K**ey、**V**alue。它不用 Mamba，而是重新设计了 RNN 结构，使其在训练时能像 Transformer 一样并行计算，在推理时退化成线性 RNN，从而兼顾训练效率和推理速度，是资源受限场景下部署长序列模型的实用选择。

```
RWKV 是另一个有趣的混合思路：

设计目标：结合 Transformer 的并行训练 和 RNN 的线性推理

训练时：像 Transformer 一样并行
推理时：像 RNN 一样线性

RWKV-6（2024）已经达到了较好的效果，
在资源受限的边缘设备上部署有明显优势
```

### 六、为什么 Transformer 还没被取代？

Mamba 在2023年底引起了很大的轰动，但到现在(2026年)，它并没有成为主流。原因是多方面的：

**原因一：效果差距依然存在**

```
在大规模评测上：

小模型（<3B）：Mamba 和 Transformer 差距不大
中等模型（7B~30B）：Transformer 仍有优势
大模型（70B+）：几乎没有大型 Mamba 纯模型

关键场景差距：
In-context Learning：Mamba 明显弱
指令跟随：Mamba 弱
复杂推理：Mamba 弱

这些恰好是大语言模型最核心的能力。
```

**原因二：生态和工程积累的巨大差距**

```
Transformer 的生态：

硬件层面：
  → GPU（NVIDIA）、TPU（Google）都针对矩阵乘法优化
  → Self-Attention 恰好就是矩阵乘法
  → 现有硬件天然支持 Transformer

软件层面：
  → Flash Attention（极致优化的注意力实现）
  → vLLM、TensorRT 等推理框架
  → 海量的工程优化积累

Mamba 的生态：
  → 没有专门的硬件优化
  → 软件框架从零开始
  → 工程成熟度远不及 Transformer
```

**原因三：Transformer 的优化还远没到头**

```
Transformer 的近期优化进展：

Flash Attention 3（2024）：
  → 又一次大幅提升注意力计算效率

Sparse Attention：
  → 不对所有词对做注意力，跳过不重要的
  → 把 O(n²) 变成接近 O(n log n)

MLA（DeepSeek）：
  → KV Cache 大幅压缩

这些优化持续压缩 Transformer 的缺点，
让 Mamba 的相对优势不断缩小。
```

**原因四：大型科技公司没有下注**

```
OpenAI、Anthropic、Google、Meta：
全部继续押注 Transformer（或 Transformer + MoE）

没有任何一家顶级实验室在主力模型上采用纯 Mamba
→ 资源、人才、工程都继续向 Transformer 集中
→ 马太效应：强者越强
```

---

### 七、Mamba 的未来在哪里？

Mamba 没有成为主流，但也没有消失。它找到了自己的位置：

```
Mamba 的现实定位（2025）：

✅ 适合的场景：
  - 超长序列的专业任务（基因组学、时序预测）
  - 资源受限的边缘部署
  - 混合架构里作为"效率层"
  - 学术研究（序列建模的理论探索）

❌ 短期内难以替代 Transformer 的场景：
  - 通用对话和指令跟随
  - 复杂推理
  - In-context Learning
  - 多模态理解
```

混合架构（Mamba + Transformer）可能是最务实的方向——在长序列效率和通用能力之间找到平衡点。

但要真正撼动 Transformer 的地位，Mamba 还需要在大规模模型上证明自己，并且等待工程生态的成熟。这条路，还很长。

### 本章小结

```
Transformer 的根本缺陷：
  Self-Attention 是 O(n²)，序列越长计算量平方级增长

SSM / Mamba 的核心思路：
  用"状态压缩"代替"全文回顾"，做到线性复杂度 O(n)

Mamba 的关键创新：
  选择性状态空间——重要内容多保留，无关内容快掠过

Mamba 的优势：
  超长序列速度快、显存省、推理无需 KV Cache

Mamba 的劣势：
  In-context Learning 弱、精确检索弱、复杂推理弱

混合架构的折中：
  Jamba（Mamba + Transformer 交替）
  Zamba（极少数共享 Transformer 层）
  RWKV（训练并行 + 推理线性）

2025年现实：
  Transformer 仍然主导
  原因：效果差距 + 生态差距 + 硬件适配 + 大厂不下注

Mamba 的定位：
  专业长序列任务 + 混合架构效率层 + 学术探索
  短期内难以成为通用大模型的主流架构
```

九个章节，覆盖了从 RNN 到 Transformer，从 BERT/GPT 的分叉，到 MoE、KV Cache 优化、Reasoning、多模态、SSM 的完整演进图谱。

## 第十章：横向总结——读懂各家模型的架构选择

### 一、回顾：架构演进的主线

九章走下来，主线其实很清晰：

```
每一代架构变化，都是在解决上一代的某个痛点

RNN/LSTM
  痛点：顺序处理、梯度消失、无法并行
  └→ Transformer 解决：并行计算 + 全局注意力

Transformer（Encoder-Decoder）
  痛点：结构复杂、扩展性差
  └→ Decoder-only 解决：简洁结构 + 无限扩展

Decoder-only 稠密模型
  痛点：参数大了推理贵
  └→ MoE 解决：专家分工 + 按需激活

长序列注意力
  痛点：KV Cache 显存爆炸
  └→ GQA / MLA 解决：共享或压缩 KV

训练数据枯竭
  痛点：Scaling Law 遇到天花板
  └→ Reasoning 解决：推理时计算换准确率

纯文字模型
  痛点：看不到真实世界
  └→ 多模态解决：统一处理多种模态

Transformer O(n²) 复杂度
  痛点：超长序列计算量爆炸
  └→ Mamba/SSM 尝试解决：线性复杂度（仍在探索）
```

现在把这些技术拼在一起，看看各家模型是怎么组合这些选择的。

### 二、架构选择地图

把主流模型的核心架构选择列成一张表：

```
模型              基础架构      注意力优化   规模策略   推理能力   多模态
─────────────────────────────────────────────────────────────────────
GPT-4o           Decoder-only   未公开       未公开      o1系列    原生多模态
Claude 3.7       Decoder-only   未公开       稠密        扩展思考   插件式视觉
Gemini 2.0       Decoder-only   未公开       MoE(推测)  有         原生多模态
─────────────────────────────────────────────────────────────────────
LLaMA 3.3        Decoder-only   GQA          稠密        无         无(基座)
Qwen3（密集版）  Decoder-only   GQA          稠密        思考模式   Qwen-VL系列
Qwen3（MoE版）   Decoder-only   GQA          MoE         思考模式   Qwen-VL系列
DeepSeek-V3      Decoder-only   MLA          MoE         R1系列     无(基座)
DeepSeek-R1      Decoder-only   MLA          MoE         GRPO训练   无
Mistral Large    Decoder-only   GQA          MoE         无         无
─────────────────────────────────────────────────────────────────────
Jamba            Mamba+Transformer GQA      MoE         无         无
RWKV-6           线性RNN        线性注意力    稠密        无         无
```

几个共同点一目了然：
- **基础架构**：清一色 Decoder-only，无一例外
- **注意力优化**：开源模型几乎全用 GQA，DeepSeek 用更激进的 MLA
- **规模策略**：大模型普遍走向 MoE，小模型仍然稠密
- **推理能力**：开始从基座模型中分离出来，成为单独的产品线

### 三、各家的差异化在哪里？

既然地基都一样，各家的差异化体现在哪里？

#### OpenAI：体验和能力的极致

```
核心策略：封闭 + 领先

架构特点：
  - 架构细节几乎不公开
  - 推测 GPT-4 是 MoE，但从未确认
  - o1/o3 系列确立了 Reasoning 范式

差异化方向：
  - GPT-4o 的实时多模态交互（语音最自然）
  - o3 在复杂推理任务上的绝对领先
  - API 生态和开发者工具最成熟

代价：
  - 最贵（API 成本行业最高）
  - 完全黑盒，无法本地部署
```

#### Anthropic：安全和推理的平衡

```
核心策略：安全优先 + 长上下文

架构特点：
  - 架构同样不公开
  - 200K 超长上下文是核心卖点
  - Claude 3.7 的扩展思考是 Reasoning 的务实实现

差异化方向：
  - 长文档处理（法律、研究、代码库分析）
  - 安全对齐做得最细致
  - 思考预算可控，成本透明

代价：
  - 多模态能力相对 GPT-4o 弱
  - 同样无法本地部署
```

#### Google DeepMind：多模态原生

```
核心策略：多模态 + 超长上下文

架构特点：
  - Gemini 从底层设计就是多模态的
  - 推测使用 MoE（从 Gemini 1.5 开始）
  - TPU 自研硬件带来训练成本优势

差异化方向：
  - 视频理解能力最强（1M token 上下文）
  - 原生音视频输入输出
  - Google 搜索、Workspace 生态集成

代价：
  - 在纯语言推理上不及 o1/Claude
  - 产品迭代节奏相对慢
```

#### Meta：开源生态的领袖

```
核心策略：开源 + 生态

架构特点：
  - LLaMA 系列定义了开源标准
  - GQA + RoPE 成为行业默认
  - 稠密模型为主，未大规模采用 MoE

差异化方向：
  - 开源权重，任何人可部署
  - 定义了开源社区的技术基准
  - Llama 3.3 70B 追平了很多闭源模型

代价：
  - 没有独立产品入口（依赖第三方部署）
  - 在 Reasoning 能力上较晚跟进
```

#### DeepSeek：效率革命者

```
核心策略：极致效率 + 开源

架构特点：
  - MoE + MLA 的组合是独特创新
  - MLA 把 KV Cache 压缩到极致
  - GRPO 替代 PPO，让 Reasoning 训练更稳定

差异化方向：
  - 训练成本远低于同等效果的竞品
  - 开源且完整（包括技术报告）
  - R1 的思考链可见，研究价值高

代价：
  - 多模态能力暂时较弱
  - 部署门槛高（671B 总参数需要大量显存）
  - 受地缘政治影响，部分场景使用受限
```

#### 阿里 Qwen：全面覆盖

```
核心策略：全场景覆盖 + 中文优化

架构特点：
  - 密集版 + MoE 版双线并行
  - 思考模式可切换（类 o1 能力）
  - Qwen-VL 系列覆盖视觉多模态

差异化方向：
  - 中文能力业界最强
  - 模型尺寸覆盖最全（0.5B 到 235B MoE）
  - 一套品牌覆盖语言/视觉/音频/代码

代价：
  - 旗舰模型效果与 GPT-4o/Claude 仍有差距
  - 产品矩阵复杂，选型容易困惑
```

### 四、一个框架：读懂任何新模型

以后看到任何新模型发布，可以用这五个问题快速理解它的架构选择：

```
问题 1：基础架构是什么？
  → 几乎必然是 Decoder-only
  → 如果不是，说明它有特殊用途（检索/嵌入）

问题 2：注意力优化用的什么？
  → GQA：主流选择，效果和效率平衡
  → MLA：DeepSeek 的激进压缩
  → MHA：老方案，通常是小模型或旧模型

问题 3：规模策略是稠密还是 MoE？
  → 稠密：部署简单，总参数即激活参数
  → MoE：总参数大，激活参数小，部署复杂但推理省
  → 关键数字：总参数 vs 激活参数

问题 4：有没有 Reasoning 能力？
  → 有思考模式：适合复杂推理，成本高
  → 没有：适合日常对话，速度快成本低
  → 可切换：最灵活（Qwen3、Claude 3.7）

问题 5：多模态支持到什么程度？
  → 纯语言基座：只处理文字
  → 插件式视觉：能看图，图文处理割裂
  → 原生多模态：图/音/视频深度融合
```

### 五、当前的技术前沿在哪里？

**方向一：Reasoning 能力的持续进化**
```
当前进展：
  - o3 在竞赛级数学上达到人类顶尖水平
  - DeepSeek-R1 开源复现，GRPO 成为标准方法

未解问题：
  - 如何减少过度思考（简单问题不需要长思维链）
  - 开放性问题的 Reasoning 如何评估和训练
  - 思维链幻觉如何系统性解决
```

**方向二：多模态统一生成**
```
当前进展：
  - GPT-4o 支持图片输出
  - Gemini 2.0 原生多模态输入输出

未解问题：
  - 高质量视频生成仍然是独立模型（Sora、Veo）
  - 统一架构的质量还不及专用模型
  - 实时视频流的处理成本极高
```

**方向三：推理效率的极致压缩**
```
当前进展：
  - MLA 把 KV Cache 压缩到 7%
  - 量化技术（INT4/FP8）让大模型可以更小显存运行
  - Speculative Decoding 让生成速度翻倍

未解问题：
  - 超大 MoE 模型的单机部署仍然困难
  - 量化和 MoE 的结合还有优化空间
```

**方向四：长上下文的真正理解**
```
当前进展：
  - 技术上能塞进 100 万 token
  - 但模型真的"理解"了这 100 万 token 吗？

未解问题：
  - "大海捞针"测试显示，模型对超长上下文中间部分
    的信息处理能力远弱于开头和结尾
  - 如何让模型对超长上下文保持均匀的注意力？
```

### 六、大模型架构的底层逻辑

走过这十章，可以提炼出几个更深层的规律：

**规律一：简洁结构 + 数据 + 算力 > 精巧设计**

```
LSTM 比 RNN 精巧 → 但被更简单的 Transformer 取代
Encoder-Decoder 比 Decoder-only 完整 → 但输给了更简单的结构
精心设计的 SSM → 暂时没有打败工程成熟的 Transformer

教训：在深度学习里，简单结构 × 大规模，
通常比复杂结构 × 小规模更有效。
```

**规律二：训练范式的改变比架构改变影响更大**

```
ChatGPT 没有改变架构（还是 GPT-3.5），
但 RLHF 让模型从"续写工具"变成了"对话助手"。

o1 的架构和 GPT-4 没有本质区别，
但 Reasoning 训练让它在复杂推理上质变。

结论：架构是"硬件"，训练范式是"软件"，
软件的升级有时候比硬件更重要。
```

**规律三：效率创新的价值不亚于效果创新**

```
DeepSeek-V3：
  效果接近 GPT-4o，但训练成本是 GPT-4 的 1/20。
  这不是"差不多的模型"，而是"降维打击"。

MLA 把 KV Cache 压缩 93%：
  不是让模型更聪明，而是让它更便宜、更快、更可及。

结论：在 AI 军备竞赛里，
"同样效果，更低成本"和"同样成本，更好效果"同样重要。
```

**规律四：开源正在重塑竞争格局**

```
2022年之前：顶级模型 = 闭源黑盒，普通人用不到
2023年 LLaMA 之后：开源社区开始赶上顶级闭源模型
2025年：开源模型（DeepSeek-V3、Qwen3、LLaMA 3.3）
         在多数任务上已经可以替代 GPT-4

这意味着：
  - 顶级 AI 能力的门槛大幅降低
  - 竞争从"能不能做到"变成"谁做得最高效"
  - 生态和应用层的竞争变得更重要
```

## 第十一章：系列回顾—每一次变化解决了什么

```
十章一句话总结：

第一章  RNN → LSTM → Seq2Seq → Attention → Transformer
        解决了：顺序依赖、长距离遗忘、信息压缩瓶颈

第二章  Transformer = Self-Attention + FFN + 位置编码
        核心优势：并行计算 + 全局关联 + 无限可扩展

第三章  BERT 选 Encoder（理解），GPT 选 Decoder（生成）
        ChatGPT 证明：Decoder-only + RLHF 才是正路

第四章  Decoder-only 赢在：简洁、数据无限、理解生成一体
        LLaMA 开源，定义了行业标准

第五章  MoE：专家分工，按需激活
        同样推理成本，模型可以做 10~30 倍大

第六章  KV Cache 是长上下文的核心矛盾
        MHA → GQA → MLA，KV 越来越小

第七章  数据枯竭，转向推理时计算
        思考 token 是草稿纸，想得越多，答得越准

第八章  多模态：从视觉编码器外挂，到原生多模态设计
        视频是最难的模态，统一生成是下一步

第九章  Mamba/SSM：线性复杂度的挑战者
        理论漂亮，现实还没赢，混合架构是折中

第十章  所有架构选择都是权衡
        简洁 × 规模 > 精巧 × 复杂
        训练范式的改变有时比架构更重要
        效率创新和效果创新同样有价值
```

大模型的架构演进还在继续。这份指南描述的是 2025 年中的快照——明年某些章节可能已经过时，某个新的突破可能正在某个实验室里等待发布。

但有一件事不会变：**每一次架构变化，都是在解决上一代的某个痛点。** 理解了这个逻辑，就能读懂任何新模型的架构选择，不管它叫什么名字。
