# 模型训练技术体系全解析（上篇）

数据决定模型能力的上限，架构和训练技巧在此基础上做效率优化。本篇覆盖这条链路的前半段：数据工程、架构选型、预训练。

---

# 一、引言

## 1.1 训练全流程概览

大语言模型的训练是一条多阶段流水线，每个阶段的决策都会向下游传导影响。

**阶段一：原始数据汇聚。** 从互联网、书籍、代码仓库、学术论文等渠道收集原始文本，规模通常在 TB 到 PB 级别，质量参差不齐。

**阶段二：数据清洗与配比。** 去重、语言过滤、质量评分、有害内容过滤，将原始数据压缩为高质量训练集。各类数据的混合比例（中文、代码、数学等）直接影响最终能力分布。

**阶段三：模型架构设计。** 确定层数、宽度、注意力机制、位置编码、激活函数。这步决定模型的能力上限和推理成本。

**阶段四：预训练（Pre-training）。** 在清洗后的数据上做自回归语言建模——预测下一个 token。耗时最长，成本最高，通常需要数千 GPU 并行运行数月。

**阶段五：后训练对齐（Post-training Alignment）。** 预训练模型只会续写文本，不懂遵从指令。通过 SFT（监督微调）、RLHF 或 DPO，将其改造为能执行指令、拒绝有害请求的助手。

**阶段六：评估与迭代。** 在 MMLU、HumanEval、MT-Bench 等 benchmark 上验证，发现短板后调整数据配比或训练策略，重新迭代。

**阶段七：部署与推理优化。** 将模型量化、蒸馏后部署到推理集群，通过 KV Cache、连续批处理、Speculative Decoding 等技术最大化吞吐量。

各阶段相互制约：数据质量决定预训练上限，架构选型影响推理成本，对齐策略决定用户体验。

## 1.2 五个核心维度

| 维度 | 核心问题 | 关键技术 |
|------|---------|---------|
| **数据** | 用什么数据训练？ | 数据采集、清洗、配比、课程学习 |
| **架构** | 模型长什么样？ | Transformer 变体、位置编码、注意力机制、MoE |
| **训练** | 怎么高效训练？ | 并行策略、混合精度、优化器、训练稳定性 |
| **对齐** | 如何让模型听话？ | SFT、RLHF、DPO、安全过滤 |
| **部署** | 如何低成本服务用户？ | 量化、蒸馏、推理框架、KV Cache |

五个维度并非独立——数据影响架构选型，架构约束训练策略，训练结果决定对齐难度，部署需求反过来影响架构设计。

# 二、数据工程：模型能力的基石

> 模型的能力边界在数据工程阶段已基本确定。架构和训练技巧是在既定数据天花板内的效率优化，数据配比和质量的决策直接影响最终表现。

## 2.1 数据来源与采集

### 主要数据来源

**网络爬取数据（Web Crawl）** 是大多数训练数据的主体。Common Crawl 自 2008 年持续爬取互联网，已积累超过 250 亿个网页快照，未压缩体积超 400TB。其中既有维基百科、学术论文这类高质量内容，也有大量低质量商业文章和论坛内容。

**公开数据集**是高质量补充：
- **The Pile**（EleutherAI）：825GB 高质量英文文本，22 个子集
- **RedPajama / SlimPajama**：LLaMA 训练数据的开源复现
- **ROOTS**：多语言语料
- **The Stack**（BigCode）：来自 GitHub 的代码数据，超 6TB

**私有数据**是顶级商业模型与开源模型之间的主要差距来源。书籍、新闻存档、医疗/法律/金融文档往往有版权保护，难以公开获取。

**多模态数据**随多模态模型兴起而重要：
- 图像-文本对：LAION-5B（58 亿对）、COYO-700M，训练视觉理解
- 代码：对提升推理和结构化输出能力有显著作用
- 音频：Common Voice、LibriSpeech，用于语音理解

### 采集工程要点

大规模爬取需解决：礼貌爬取（遵守 robots.txt、控制请求频率）、正文提取（去除导航栏和广告）、URL 去重。常用工具：Scrapy、Trafilatura（正文提取）、Resiliparse（大规模 HTML 处理）。

## 2.2 数据清洗与预处理

原始网络爬取数据中超过 80% 需要过滤。未经清洗的数据会让模型学到大量噪声，甚至习得有害行为。

### 去重：MinHash 与 SimHash

网络上大量内容是重复或高度相似的——转载文章、SEO 内容、镜像站。重复数据会让模型对其"记忆"超过应有权重，导致知识分布失衡，浪费训练算力。

**MinHash 原理：** 将文档分成 n-gram 片段，用多个哈希函数各自取最小值组成签名。两篇文档的 MinHash 签名越相似，其 Jaccard 相似度（交集/并集）越高。通过 LSH（局部敏感哈希）将候选对数从 O(n²) 降至接近线性，使数十亿文档规模的去重成为可能。

**SimHash：** 将文档中每个词的哈希值加权求和，得到固定长度的二进制指纹。相似文档的指纹汉明距离近（不同位数少）。SimHash 更适合近似重复检测，MinHash 更适合模糊相似度估计。

实践中通常两阶段结合：精确去重（MD5/SHA，去除完全相同文档）+ 模糊去重（MinHash LSH，去除高相似度文档）。

### 质量过滤

**语言识别：** 使用 fastText 或 langdetect 对文本分类，过滤与目标语言不符的内容。多语言模型按目标语言分布采样。

**困惑度过滤：** 用预训练好的小型参考语言模型（如 KenLM）计算文档困惑度。困惑度高意味着文本语言不流畅，可能是乱码或低质量内容。设置阈值（保留困惑度低于某值的文档）是需要人工校验的工程决策。

**规则过滤：**
- 文档长度过滤（过短片段通常是导航文字、按钮等）
- 字符级过滤（非字母字符比例过高可能是乱码）
- 文档内重复段落过滤（模板页面或爬虫错误的特征）
- 停用词密度检查（正常文本含一定比例功能词）

**有害内容过滤：** 分两层——关键词/URL 黑名单快速粗过滤 + 预训练分类模型细粒度打分。注意过度激进的过滤会误伤正常文本（历史暴力事件的学术文章、医学敏感词），导致模型在这些领域能力下降。

## 2.3 数据配比与调度

### 领域权重设计原则

**代码数据的杠杆效应：** 即使目标是自然语言能力，混入 5%—20% 的代码数据也能显著提升逻辑推理能力。代码的结构性和严谨性能强化模型的推理质量。

**高质量数据上采样：** 书籍、学术论文知识密度高，但在互联网数据中占比偏低。通常对这类数据重复使用 2—10 次，抵消其在原始数据中的低比例。

**语言配比：** 按互联网语言分布配比会导致英文主导。多语言模型通常需要对低资源语言大幅上采样，以保证多语言能力。

### 课程学习：动态数据调度

课程学习将由简到难的学习策略用于模型训练，最常见形式是数据混合动态调度：

- **早期阶段：** 以通用网络文本为主，建立基础语言能力
- **中期阶段：** 逐步提高书籍、论文等高质量来源的比例，提升知识密度
- **Cooldown 阶段（后期）：** 大幅提高高质量数据比例，在"冲刺阶段"强化关键能力

**数据回放（Data Replay）：** 训练新领域数据时混入少量之前的通用数据，防止灾难性遗忘。

### Scaling Law 与数据量估算

Chinchilla Scaling Law（Hoffmann et al., 2022）的核心结论：**给定算力预算，最优的模型参数量与训练 token 数之比约为 1:20。** 即 7B 参数模型最优训练约 140B token。

注意 Chinchilla 是针对训练损失最优化的结论。工程实践中还要考虑推理成本——如果推理成本是约束，应该用更多数据训练更小的模型（LLaMA 3 8B 用了 15T token，远超 Chinchilla 最优点）。

## 2.4 实践选型建议

### 开源数据集推荐

| 数据集 | 规模 | 特点 | 适用场景 |
|--------|------|------|---------|
| **FineWeb**（HuggingFace） | 15T tokens | 高质量英文网络文本，过滤流程完整 | 英文通用预训练首选 |
| **SlimPajama** | 627B tokens | RedPajama 的精简高质量版本 | 资源有限时的快速起点 |
| **Dolma**（AI2） | 3T tokens | 多来源混合，透明度高 | 研究复现、可解释性要求高 |
| **The Stack v2** | 900B tokens | 多语言代码，来源清晰 | 代码能力强化 |
| **ROOTS** | 1.6TB | 46 种语言 | 多语言模型 |

### 数据量与质量的权衡

- **<100B tokens：** 质量远比数量重要。少量高质量数据训练的模型通常好于大量低质量数据。
- **100B—1T tokens：** 质量和数量并重。需要完善的清洗流水线，同时扩大数据来源。
- **>1T tokens：** 数量发挥更大作用，但仍需持续迭代清洗策略。

**决策建议：**
- GPU 充足但人力有限 → 直接用 FineWeb 等已过滤的数据集
- 做中文模型 → 基于 Common Crawl 中文部分自建清洗流水线，或使用 WanJuan、SkyPile 等中文数据集

### 小团队最简可行方案

优先级排序：

1. **直接用现成数据集**（FineWeb / Dolma）作为基础，避免从头建清洗流水线
2. **加领域专用数据：** 垂直领域模型，混入 3%—10% 领域数据
3. **最关键的清洗步骤：** 精确去重 > 语言过滤 > 长度过滤，MinHash 模糊去重可以延后
4. **小规模实验验证配比：** 在 1% 数据上跑消融实验，确定领域权重后再全量训练

**工具推荐：** DataTrove（HuggingFace）是目前最完整的开源数据处理框架，覆盖从爬取到去重的全流程。

# 三、模型架构设计

> 架构选型的核心是适配约束，而非追新。7B 和 700B 模型的选型问题截然不同；训练阶段的架构选择还需兼顾推理阶段的部署成本。

## 3.1 主流架构演进

### 注意力机制

Transformer 的核心是注意力机制：对序列中的每个位置，计算它与序列中所有其他位置的相关程度（注意力分数），然后加权求和得到新的表示。

计算公式：

```
Attention(Q, K, V) = softmax(QK^T / √d_k) × V
```

- Q（Query）：当前位置在查询什么
- K（Key）：每个位置有什么标签
- V（Value）：每个位置的实际内容

每个位置可以直接关注序列中任意其他位置，不受距离限制。代价是计算复杂度 O(n²)，序列越长计算量越大——这是长上下文是技术挑战的根本原因。

### Decoder-only 成为主流的原因

早期 Transformer 分为三派：Encoder-only（BERT）、Encoder-Decoder（T5、BART）、Decoder-only（GPT）。

Decoder-only 成为主流的原因：

1. **统一框架：** 所有 NLP 任务都可表述为"生成"——分类是生成标签，翻译是生成目标语言，问答是生成答案。一个模型通过 prompt 处理所有任务。
2. **Scaling 特性更优：** 参数量和数据量增加时，能力提升更平滑可预测。
3. **KV Cache 工程优势：** 推理时可缓存已生成内容的 Key-Value 状态，避免重复计算。
4. **GPT-3 的规模验证：** 2020 年展示的惊人 Few-shot 能力使行业快速向这一路线集中。

### LLaMA 架构：业界基线

LLaMA 2/3 的架构组合代表了效率与性能之间的最优平衡，已成为业界"默认基线"：

- Pre-RMSNorm（前置归一化 + RMSNorm）
- SwiGLU 激活函数
- RoPE 位置编码
- GQA（分组查询注意力）
- 无偏置项（No Bias）

## 3.2 关键架构组件

### 位置编码

Transformer 的注意力机制本身是无序的——不知道词语的先后顺序。位置编码给每个 token 附加位置信息，让模型感知顺序。

**RoPE（旋转位置编码）：** 不直接编码绝对位置，而是编码相对位置距离。通过对 Q 和 K 向量做与位置相关的旋转变换，使注意力分数中自然包含相对位置信息。

RoPE 的关键优势是外推能力：通过 YaRN、RoPE Scaling 等技术，可以在原始上下文长度基础上大幅扩展。LLaMA 3 的 128K 上下文即基于 RoPE 扩展实现。

### 多头注意力：MHA → GQA → MQA

多头注意力（MHA）让不同的头专门学习不同类型的依赖关系：有的头关注语法，有的关注语义相似性，有的关注指代。但多头带来较大的 KV Cache 占用，催生了 GQA 和 MQA。

| 方案 | KV Cache 大小 | 质量 | 推理速度 | 代表模型 |
|------|--------------|------|---------|---------|
| **MHA** | 最大（H 份） | 最优 | 最慢 | GPT-2、早期 LLaMA |
| **GQA** | 中等（G 份） | 接近 MHA | 较快 | LLaMA 2 70B、LLaMA 3 |
| **MQA** | 最小（1 份） | 略低 | 最快 | Falcon、PaLM |

GQA 是当前主流选择：多个查询头共享少量 KV 头，在质量和效率之间取得良好平衡。

### 激活函数：SwiGLU

SwiGLU = Swish 激活 + GLU（门控线性单元）。FFN 层改为门控结构，网络可以动态"开关"不同的神经元路径。在相同参数量下，SwiGLU 通常比 GeLU 给出更低的训练损失。LLaMA 全系列采用 SwiGLU。

### 归一化：Pre-Norm + RMSNorm

深层网络训练时，中间层激活值分布容易漂移（梯度消失或爆炸）。归一化将每层输入拉回到稳定分布，让训练更稳定。

- **Pre-Norm：** 将归一化移到每个子层的输入，而非输出。训练更稳定，现代大模型几乎全部采用。
- **RMSNorm：** 去掉均值中心化，只保留 RMS 缩放。计算速度比 LayerNorm 快约 10—15%，性能损失可忽略。

## 3.3 MoE 架构

### 核心思想：稀疏激活

传统 Dense 模型的每个参数都参与每个 token 的计算。MoE 将 FFN 层替换为多个并行的"专家"网络，每次只激活其中少数几个（通常 2 个）处理当前 token。

结果是：**参数量巨大，但推理时的计算量（FLOPs）只与激活专家数成比例，而非总参数数。**

### 路由机制（Top-K 路由）

路由器（Router）接受当前 token 的表示，输出每个专家的打分，选择分数最高的 K 个专家（通常 K=2）处理该 token。

**负载均衡问题：** 如果所有 token 都倾向于路由到同几个专家，其余专家闲置（"专家坍塌"）。通过引入辅助损失惩罚不均衡分配来解决。

### MoE vs Dense 成本对比

| 维度 | Dense 模型 | MoE 模型 |
|------|-----------|---------|
| **推理计算量** | 与参数量成正比 | 与激活参数量成正比（更低） |
| **内存占用** | 与参数量成正比 | 与**总**参数量成正比（全部专家都需加载） |
| **工程复杂度** | 低 | 高 |

**关键陷阱：** MoE 降低的是计算量（FLOPs），并不降低内存占用。Mixtral 8x7B 推理时只激活约 13B 参数，但仍需在显存中存放全部 47B 参数。

## 3.4 实践选型建议

### 各规模推荐配置

以 LLaMA 3 为参考，适合大多数预训练场景：

| 规模 | 层数 | 隐层维度 | 注意力头数 | KV 头数（GQA） |
|------|------|---------|----------|--------------|
| **7B** | 32 | 4096 | 32 | 8 |
| **13B** | 40 | 5120 | 40 | 8 |
| **70B** | 80 | 8192 | 64 | 8 |

所有规模均推荐：**Pre-Norm + RMSNorm + SwiGLU + RoPE + GQA + 无偏置项**。

### 何时考虑 MoE

**适合 MoE：**
- 计算预算充足但推理计算量受限
- 追求极致模型能力
- 显存不是瓶颈（有充足多卡推理资源）

**不适合 MoE：**
- 小团队、有限显存
- 训练数据有限（路由器需要足够多 token 才能学会有效分配）
- 工程资源紧张

### 长上下文需求下的架构调整

应用场景需要 32K 以上上下文时，建议：

1. 从一开始就使用 **GQA**（而非 MHA），将 KV Cache 从 H 份压缩到 G 份
2. 选择支持 **YaRN** 的 RoPE 实现，方便后期扩展上下文
3. 启用 **FlashAttention**（IO 优化，大幅减少显存读写，不改变架构逻辑）

这两个选择将在后期扩展上下文时节省大量重训成本。

# 四、预训练（Pre-training）

预训练是模型能力的根基。核心思路是：在海量无标注文本上做自回归语言建模，无需人工标注，仅凭"预测文字"这一个任务，就能涌现出理解、推理、代码等复杂能力。

---

## 4.1 训练目标

### 自回归语言建模（CLM）

训练目标是最大化条件概率：

```
P(x₁, x₂, ..., xₙ) = ∏ P(xₜ | x₁, ..., xₜ₋₁)
```

每一步，模型只能看到当前位置之前的所有 token，然后预测当前 token。这种"只看过去、预测现在"的设定天然适合生成任务。

**为什么简单的"预测下一个词"能产生强大能力？** 要准确预测下一个词，模型必须理解语义、语法、逻辑和世界常识——这些能力在数据量和模型容量足够大时会自然涌现。

实现细节：
- 标签是输入序列向右移一位（teacher forcing）
- 损失函数：`loss = CrossEntropy(logits, labels)`
- Causal Mask 保证每个位置只能 attention 到自身及左侧 token

### 多任务联合预训练

现代预训练通常混合多种数据格式，形成隐式的多任务训练：

| 数据类型 | 占比（参考） | 能力目标 |
|---------|------------|---------|
| 网页文本（Common Crawl 等） | ~50-70% | 通用语言理解 |
| 代码（GitHub 等） | ~10-20% | 逻辑与结构化推理 |
| 书籍、论文 | ~10-15% | 长程依赖、学术知识 |
| 问答、对话 | ~5-10% | 指令跟随的早期信号 |

代码数据的价值超出预期——即使是非代码任务，代码训练也能大幅提升模型的逻辑推理能力。

---

## 4.2 优化器与超参数

### AdamW 核心参数

**β1（动量系数，典型值 0.9）：** 对历史梯度方向做指数平滑。β1=0.9 意味着当前更新方向有 90% 来自历史方向，10% 来自当前梯度。抑制噪声梯度导致的方向突变，让参数更新更平稳。

**β2（二阶矩系数，典型值 0.95~0.999）：** 记录每个参数方向上梯度平方的历史均值，用于自适应学习率——更新频繁的方向学习率自动缩小，稀疏更新的方向保持相对更大的学习率。大模型通常用较小的 β2（如 0.95），以便更快响应当前梯度变化。

**Weight Decay（权重衰减，典型值 0.1）：** 每次更新将参数向零方向拉动，防止参数过大。AdamW 将 weight decay 从梯度中解耦，直接作用于参数本身，与 Adam 的 L2 正则化行为不同，训练效果更好。

### 学习率调度：Warmup + Cosine Decay

- **Warmup 阶段（前 1-5% steps）：** 从极小值线性增长到峰值学习率。初期参数随机初始化，梯度波动剧烈，直接用大学习率会破坏初始状态。
- **稳定训练阶段：** 用峰值学习率持续训练。
- **Cosine Decay 阶段（后期）：** 学习率以余弦曲线缓慢下降到峰值的 10% 或更低，帮助模型细化收敛。

```python
def get_lr(step, warmup_steps, total_steps, max_lr, min_lr=1e-5):
    if step < warmup_steps:
        return max_lr * step / warmup_steps
    progress = (step - warmup_steps) / (total_steps - warmup_steps)
    return min_lr + 0.5 * (max_lr - min_lr) * (1 + math.cos(math.pi * progress))
```

**参考峰值学习率：**
- 7B 模型：3e-4
- 13B 模型：2e-4
- 70B 模型：1e-4（模型越大，学习率通常越小）

### Batch Size 与学习率的关系

**Linear Scaling Rule：** Batch Size 翻倍，学习率等比例翻倍。

原理：Batch Size 越大，梯度估计方差越小，可以"迈更大的步"。当 Batch Size 超过 1M tokens/step 时，线性规则逐渐失效，改用 **Square Root Scaling**：`lr ∝ sqrt(batch_size)`。

## 4.3 训练稳定性

### 损失尖峰（Loss Spike）

训练损失从低位突然飙高，可能自动恢复，也可能不会。

**常见成因：**
1. 异常数据批次：某个 batch 混入格式异常或超长文本，梯度爆炸
2. 学习率过高：更新步幅太大，冲过最优点
3. 梯度爆炸：某层梯度数值突然异常大
4. 数值不稳定：BF16 运算下的精度丢失累积

**排查步骤：**
- 检查 gradient norm 曲线，看尖峰前是否有梯度异常
- 检查对应的训练数据 batch（事先保存 batch index）
- 定位是否由特定数据源引起
- 从 spike 前的 checkpoint 降低学习率重启

### 混合精度训练：BF16 优于 FP16

| 格式 | 总位数 | 指数位（数值范围） | 尾数位（精度） |
|------|-------|----------------|-------------|
| FP32 | 32 | 8位 | 23位 |
| BF16 | 16 | **8位** | 7位 |
| FP16 | 16 | 5位 | 10位 |

BF16 的指数位和 FP32 相同（8位），能表示的数值范围相同（约 ±3.4×10³⁸）。FP16 指数位只有 5 位，最大表示 65504——大模型训练中梯度或激活值超过此值会**溢出成 NaN**，导致训练崩溃。

BF16 精度低于 FP16，但对深度学习而言，**范围比精度更重要**。

**推荐配置：** 模型参数和激活值用 BF16，梯度累积用 FP32。

### 梯度裁剪

当梯度的全局 L2 范数超过阈值 `max_norm` 时，等比例缩小所有梯度，防止训练崩溃：

```python
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
```

推荐 `max_norm=1.0`，大模型可用 `0.5` 更保守。

## 4.4 Scaling Law 与训练决策

### Chinchilla Law

Chinchilla 论文（DeepMind, 2022）的核心结论：**最优训练配置下，模型参数量（N）与训练 token 数（D）应近似相等地扩展，具体建议 `D ≈ 20 × N`。**

| 模型参数量 | 最优训练 Token 数 | 代表模型 |
|----------|----------------|---------|
| 7B | ~140B tokens | 许多开源 7B 仅用此量 |
| 13B | ~260B tokens | - |
| 70B | ~1.4T tokens | Llama 2 70B |
| 7B（强化版） | 1T+ tokens | Llama 3 8B（超训练）|

**近年新趋势：** 当推理成本比训练成本更重要时，用小模型超量训练（LLaMA 3 8B 训练了 15T token，远超 Chinchilla 最优），以更低的部署成本换取更强的能力。

### 计算量估算

```
总 FLOPs ≈ 6 × N × D
（N=参数量，D=Token 数量，6 是前向+反向的近似系数）

示例：7B 模型 × 1T tokens
FLOPs = 6 × 7×10⁹ × 10¹² = 4.2×10²² FLOPs

A100 GPU 算力 ≈ 3.12×10¹⁴ FLOPs/s（BF16）
所需 GPU 时间 = 4.2×10²² / 3.12×10¹⁴ ≈ 1.35×10⁸ GPU-秒
折合 100 张 A100 ≈ 15.6 天
```

## 4.5 实践选型建议

### 超参数起点

| 模型规模 | Batch Size（tokens） | 峰值 LR | Warmup Steps | 权重衰减 |
|---------|---------------------|--------|-------------|--------|
| 1-3B | 1M~2M | 3e-4 | 1000 | 0.1 |
| 7B | 2M~4M | 2e-4~3e-4 | 2000 | 0.1 |
| 13B | 4M | 2e-4 | 2000 | 0.1 |
| 70B | 4M~8M | 1e-4 | 2000 | 0.1 |

通用起点：`β1=0.9, β2=0.95, ε=1e-8, gradient_clipping=1.0, weight_decay=0.1`（不对 LayerNorm 和 bias 做衰减）

### 预训练监控指标

| 指标 | 正常状态 | 异常信号 |
|------|--------|--------|
| Training Loss | 持续下降 | 不降反升、剧烈抖动 |
| Gradient Norm | 0.5-2.0 | 持续 >10 或 NaN |
| Learning Rate | 按计划变化 | 意外不变 |
| GPU 显存利用率 | >85% | 骤降（可能 OOM 后重启） |
| MFU（模型浮点利用率） | >40% | 过低说明通信瓶颈 |

### 常见训练失败排查

- [ ] **Loss 从未下降：** 学习率太大/太小、数据格式错误、tokenizer 与模型不匹配
- [ ] **Loss Spike 且不恢复：** 数据中有毒样本、学习率过高、梯度裁剪值过大
- [ ] **OOM（显存溢出）：** 减小 micro batch size、开启梯度检查点、检查序列长度
- [ ] **训练速度远低于预期：** 通信瓶颈、DataLoader 成为瓶颈、未开启 Flash Attention
- [ ] **模型不收敛也不发散：** 检查学习率调度是否有 bug，检查数据是否已打乱
